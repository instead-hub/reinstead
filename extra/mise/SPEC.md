# mise — спецификация DSL

`extra/mise/mise.py` — транспайлер декларативного DSL (`.mise`) в обычный
Lua для INSTEAD/МЕТАПАРСЕР 3. На выходе — стандартный `main3.lua`
(или `main3-ru.lua` / `main3-en.lua`), который можно запускать без Python.

```
python3 extra/mise/mise.py game.mise -o main3.lua
```

## Структура файла

Файл состоит из секций и деклараций:

```
name: Судный день
version: 0.1
author: Пётр Косых
info: Короткая зарисовка об одиноком космонавте.
lang: ru
fmt: dash, quotes
require: snd

const:
  ...

global:
  ...

setup:
  ...

patch объект:
  ...

fn имя(параметр: тип, ...) -> тип:
  ...

obj имя:
  ...

room имя:
  ...

talk Диалог:
  ...

verb Имя:
  ...

lua:
  |lua
  -- аварийный выход: произвольный Lua в этом месте
```

- `name/version/author/info` — метаданные (`--$Name:...$` и т.п.).
- `lang: ru|en` — какая языковая прослойка подключается (`parser/mp-ru`/`mp-en`).
- `fmt: dash, quotes` — флаги `fmt.*`.
- `require: snd` — дополнительные `require`.
- `include: stdlib` — подключить общую библиотеку `fn` (см. ниже).
- `event Имя:` — объявление события (и, при желании, его действия, см. ниже).
- `const:` — объявления `const 'имя' (значение)` (read-only, не сохраняются).
- `global:` — объявления `global 'имя' (значение)` (сохраняются в сейвах).
- `setup:` — мир/игрок/общие обработчики (см. ниже).
- `patch объект:` — правка существующего объекта/модуля (`@compass`, `game`).
- `fn имя(параметр: тип, ...) -> тип:` — именованный кусочек/обработчик (см. ниже).
- `type имя: значения` — перечисление (см. ниже).
- `extend type имя: значения` — расширить перечисление.
- `lua:` — вставка произвольного Lua (escape hatch).

Имена и теги (`obj имя:`, `room #зал:`, `patch game:`, `extend #Take:`),
события, `attrs:` и элементы списков пишутся **голыми** — кавычки в них
запрещены (ошибка компиляции). Строковые значения остаются как были:
тексты, `words:`, `say '...'`.

Отступы — пробелы (таб = 3); вложенность задаётся отступом. Пустые строки
игнорируются. Комментарий — `#` в начале строки или отдельным словом
(окружённый пробелами).

## Значения (типизация литералами)

Тип значения задаётся формой записи:

| Литерал | Тип |
|---|---|
| `[[...]]`, `[==[...]==]` | строка (может быть многострочной) |
| `"..."`, `'...'` | строка (однострочная) |
| `2`, `-1`, `3.14` | число |
| `true`, `false`, `nil` | булево/nil |
| `{ ... }`, `[ ... ]` | табличный литерал (Lua), читается до баланса скобок |
| `` `expr` `` | сырое Lua-выражение (вставляется дословно) |
| голый текст | см. правила ниже |

Голые значения:

- в «текстовых» ключах (`description`, `dsc`, `title`, `inv`, `words`,
  `text`, `when_*`, `cant_go`, `ask`, `reply`, `say`, `intro` и т.п.) и в
  значениях обработчиков — это **текст** (становится `[[...]]`); запятые и
  прочие символы — часть текста;
- в остальных местах — либо **ссылка на объект** (если совпадает с
  объявленным id → `_'id'`), либо строка (если id не объявлен);
- списки через запятую (`attrs: worn, clothing`, `with: gate, lever`)
  разбираются как список значений;
- табличные литералы (`{...}`/`[...]`) распознаются в нетекстовых
  ключах — например, `phr: { ... }`, `hint_verbs: { "#Exam" }`;
- списки строк/шаблонов — через `-`-пункты:

```
  patterns:
    - {noun}/вн : Tune
    - частоту|канал : Tune
```

## Типы полей и переменных

Поля объектов типизируются по литеральному значению объявления
(`числа` → `num`, `true/false` → `bool`, строки → `str`, `{...}` → `tbl`,
`nil` → `nil`, обработчики → `any`); у классов поля наследуются, у
экземпляров — дополняются своими. Тип известен для прямых ссылок
(`key.num`, `pole.has_been_saluted`), не для `s.field` с параметром.

Голое значение в поле объекта/класса — это **имя-символ**, а не строка.
Порядок: объявленный объект → тип `obj`; известное событие → `event`;
значение объявленного перечисления → его тип; иначе — ошибка
(«unknown name … in field …»). Строки пишутся явно: `[[...]]`/`"..."`.

Для `obj` в объявлении остаётся строка-имя (движку она и нужна), а
**чтения оборачиваются в `_(...)`** — движок резолвит имя в объект в
рантайме (ср. `ini` в оригинале). Поэтому forward-ссылки на объявленные
позже комнаты/объекты безопасны. Явный объект (`_'имя'` в бэктиках)
резолвится сразу и не оборачивается.

`s.field` типизируется по полям владельца и внутри тел объектов, и
внутри классов (owner-контекст); у безымянных объектов и для
неизвестных полей тип остаётся `any`.

Локальные переменные: `local x` (без значения) и `local x = nil` —
«без типа» (`any`); первое конкретное присваивание фиксирует тип, все
следующие обязаны быть совместимыми (`local x = 1; x = 'a'` — ошибка).
Переменная «obj или nil» берётся из `?`-источника (`local o = where(x)`)
или параметра `o: obj?`: тогда допустимы и `o = obj`, и `o = nil`.
Смена типа поля (`key.flag = 1` при `flag: false`) — ошибка.

## nil и optional-типы (`T?`)

- `nil` — отдельный тип; `T?` — «`T` или `nil`» (например `obj?`).
- Совместимость односторонняя: `obj` можно туда, где ждут `obj?`, но
  `obj?` в `obj` — ошибка; методы и `obj`-параметры требуют не-nil.
- Сужение в `if` (простые условия по имени, в т.ч. цепочки через `and`):
  - `if o:` / `if o ~= nil:` → в ветке `o: obj`;
  - `if o == nil:` / `if not o:` → в ветке `o: nil`;
  - у одиночного `if` с `else` ветка `else` получает обратное сужение.
- После `if` сужения нет; объявляйте `local o = ...` и работайте в ветке.
- Пример: `fn seen(w: any) -> obj?` (stdlib):

```
local o = seen 'ключ'
if o:
  o:attr 'open'      # ок, o сужен до obj
o:attr 'open'        # ошибка: возможно nil
```

## Декларации

```
obj        — обычный объект
scenery    — объект с атрибутом scenery
room       — комната
door       — дверь
story      — cutscene
ending     — gameover
dlg        — диалог (сырой phr-литерал)
talk       — диалог в DSL (см. ниже)
verb       — глагол
class      — класс (Class { ... }, см. ниже)
Имя        — экземпляр класса (любой вид с большой буквы)
```

Идентификатор: `obj ключ` или `obj "имя с пробелами"`. Имя декларации —
это и есть имя объекта в движке (`nam`), отдельного поля `nam:` нет.
Повторяющиеся имена допустимы **только для тегов** (`obj #окно:` в разных
комнатах); два обычных `obj кухня:` — ошибка компиляции. Имя можно не
указывать (`obj:`, `scenery:` и т.п.) — тогда `nam` не задаётся
(автоименованный объект).

Общие поля:

| Поле | Смысл |
|---|---|
| `words: скафандр,сумка\|мешок` | словарные слова → `-"..."`; список из строк даёт алиасы через `\|` (`,` внутри строки — синонимы) |
| `word: \|` | динамические слова: `append ...`/`say ...` (`-"..."` — no-op) |
| `attrs: worn, clothing` | атрибуты → `:attr '...'` |
| `dict: { ["форма/п"] = "текст" }` | словарные формы → `:dict { ... }` |
| `disabled: true` | `:disable()` |
| `on:` | обработчики событий (см. ниже); префикс — в ключе (`before Walk:`, `after Pull, Transfer:`) |
| `Any:`, `Default:` | `before_Any` / `before_Default` |
| `with:` | вложенные декларации (`obj:`/`obj имя:`, в т.ч. автоименованные) **или** список ссылок (`obj = {...}`) |
| `found_in: room1, room2` | где появляется объект |
| `n_to/e_to/...`, `in_to`, `out_to`, `u_to`, `d_to` | переходы (значение — комната, дверь или логика/функция) |
| `door_to`, `next_to`, `talk_to`, `with_key` | как в API |
| `description`, `dsc`, `title`, `inv`, `when_open`, … | текст/логика/Lua |
| `daemon`, `onenter`, `onexit` | обработчики-поля |
| `text:` | страницы cutscene (несколько `text:` → список) |

Обработчики:

```
obj камень:
  on:
    Take: Куда мне его.
    after Put: |
      say Ты положил камень.
      stop
    Enter, Climb: |
      wear_item(s)
  before Pull, Transfer: |lua
    ...
  with:
    obj ядро: ...
```

- ключ — имя события **точно как в движке** (`Take`, `Enter`, `SwitchOn`,
  `Any`, `Default`); нижний регистр не допускается;
  прямые ключи `before Turn, Tune:`, `after Play:` и т.п. работают и вне
  блока `on:`;
- несколько событий в одном ключе (`Enter, Climb:`) для объекта
  компилируются в один комбинированный ключ движка
  `["before_Enter,Climb"] = ...` (как в оригинальных играх); для
  `pl.`/`game.`/`patch` — в отдельные поля;
- значение — одна строка текста, `pass` (обработчик `return false`),
  блок `|` (чистая логика), `|lua` (Lua) или `use имя`
  (ссылка на именованный `fn`);
- параметры можно задать явно: `Default(s, ev, w):`, `on(s, w):`.

## Логика (`|`)

Блоки логики и Lua задаются маркером `|`/`|lua`; конец — по отступу
(отдельная закрывающая строка не нужна). Форма с закрывающим `~~~` удалена.

```
include: stdlib

Take: |
  say Ты взял камень.
  line
  append !!!
  stop

fn here() -> obj: |lua
  return here()
```

Операторы (по одному в строке, вложенность отступами):

| Оператор | Lua |
|---|---|
| `say ...`, `line`, `append ...` | вызовы `fn say/line/append` |
| `stop` / `pass` | `return` / `return false` |
| `return expr` | `return expr` |
| `x = expr`, `x += expr`, `x -= expr` | присваивание |
| `if cond:` / `elseif cond:` / `else:` | `if ... then ... end` |
| `for header:` | `for ... do ... end` (числовые границы — `num`) |
| `local a, b = ...` | локальные переменные |
| `break` | выход из цикла |
| вызов `f(...)` (fn) или присваивание | оператор |

Ошибки внутри блока логики сообщаются с номером строки (`logic:12`).

`|` — жёсткое подмножество Lua, проверяемое на этапе компиляции:
запрещены `while`/`repeat`/`goto`, анонимные функции, `function`,
длинные операторы вне грамматики. Вызовы движка в `|` запрещены:
разрешены только параметры, локальные, объявленные объекты, глобальные
игры (`global:`/`const:`), вызовы `fn`. Значения
`mp`/`std`/`game`/`pl`, вызовы методов (`s:has`, `s:once`,
`mp:xaction`), чистые функции Lua (`pairs`, `math`, `tostring`, ...)
и конструкторы таблиц `{...}` — ошибка: оборачивайте в `fn`.
Непокрытое — только через `|lua`.

`say`/`line`/`append` — обычные `fn` из `include: stdlib`
(`say(text: str, ...)`, `line()`, `append(text: str)`). Аргумент
`str`-параметра без скобок считается выражением, только если начинается
с кавычки, `(`, `_`, `#`, числа или известного имени; иначе весь текст —
строка. Склейка — через выражение или скобки: `say 'a' .. b`,
`say(a .. b)`, `say it(w), ' x'`.

Переписывание выражений:

- объявленное имя → `_'имя'`; прямо аргументом вызова скобки добавляются:
  `go_to space2` → `go_to(_'space2')`;
- имя-тег: `#окно` → `_'#окно'` (только для объявленного тега; `#`
  больше нигде не поддерживается — длину берите `len(...)`, а свою
  логику над таблицами прячьте в `fn`);
- **объекты — только голыми именами**: `obj`-параметр (`have телефон`),
  приёмник метода (`w:move зал`), сравнение (`w == имя`), поля-ссылки
  (`with`, `found_in`, `n_to`/`out_to`/`door_to`/`talk_to`/...) и `return`
  имени объекта (`return Тронный_зал`). Строка, совпадающая с именем
  объекта, — ошибка компиляции; кавычки для объектов не используются
  вообще;
- **`^` запрещён** — сравнение объектов только через `==`;
- **имена объявлений — идентификаторы** (`[#\w]+`, без пробелов/дефисов):
  `room Тронный_зал:`, `obj #глаза_совы:`;
- `str`/`num`/`bool`-параметры проверяются на тип; `obj`-параметр с
  числом/строкой — ошибка.

Что нельзя записать «простым именем» (и почему):
- имена с пробелами/дефисами недопустимы у объектов — переименуйте
  (`Тронный_зал`, `ледяное_пламя`);
- динамические ссылки `_('@'..t)` — остаются вызовом `_`;
- `|lua`/`lua:` не переписываются — там `_'...'` пишется как в Lua.

## fn и use (кусочки кода)

Именованный кусочек описывается вне объекта; на него можно сослаться
по имени (`use`) или вызвать из `|`:

```
fn cable_connect(s: obj, wh: obj): |
  if wh ^ 'Вездеход':
    ...

fn move_to(s: obj, where: obj): |lua
  move(s, where)

obj Кабель:
  on:
    Insert, Activate: use cable_connect
```

- `fn имя(параметр: тип, ...) -> тип:` — блок `|` (проверяется) или
  `|lua` (небезопасный escape hatch); компилируется в
  `local function fn_имя(параметры) ... end` (префикс `fn_` исключает
  коллизии с движком; вызовы тоже компилируются в `fn_имя`);
- тело-выражение в бэктиках — inline: `fn len(v: tbl) -> num: `#v``
  подставляется в место вызова (в скобках) и не эмитится; параметр не
  должен встречаться больше одного раза, `...` и `use` запрещены;
- типы: `obj` (объект/комната/тег), `str`, `num`, `bool`, `any`,
  `event` (событие движка/игры), `tbl` (непрозрачная таблица/список;
  элементы не типизируются);
  без аннотации — `any`; возвращаемый тип после `->` (по умолчанию `any`);
  последний параметр `...` делает `fn` вариативной (`fn say(text: str, ...)`);
- **скобки необязательны**: при одном параметре (`go_to space2`,
  `say привет`) и без параметров (`line`, `box:once`, `here.rotate`,
  `player`); `()` можно писать всегда (`line()`, `if fn() and fn2()`);
  при двух и более параметрах скобки обязательны;
- нуль-параметровые `fn` в выражениях вызываются автоматически (в т.ч.
  перед `.`/операторами): `here.rotate` → `fn_here().rotate`;
- **`str`-параметр забирает сырой текст**: `music theme.ogg` — это
  `fn_music([[theme.ogg]])`, кавычки не нужны; выражение — если аргумент
  начинается с кавычки, `(`, `_`, `#`, числа или известного имени
  (`say 'a' .. b`, `say it(w), ' x'`);
- `obj:fn(аргументы)` — синоним `fn(obj, аргументы)`: `box:has('open')`
  → `fn_has(_'box', 'open')`, `here():hasnt('open')` тоже работает;
- без скобок — один хвостовой аргумент, и только для `str`-параметра:
  `radio:hasnt on` → `fn_hasnt(_'radio', [[on]])`; голый `~атрибут`
  (`s:attr ~on` → `fn_attr(s, [[~on]])`) — тоже текст; если второй параметр
  не `str` (obj/num/bool) — ошибка, нужны скобки
  (`box:inside(container)`); без аргументов — `box:once` или
  `box:once()`;
- в `|`-теле `fn` операторы `return`/`pass`/`stop` проверяются на
  соответствие `-> тип` (включая вложенные `if`/`for`); `pass` — это
  `bool`, `stop` — `nil`;
- вызов из `|` проверяется: арность и типы аргументов, тип результата
  участвует в дальнейших проверках (`random(n: num) -> num` можно
  складывать, `str` — нет);
- **`obj`-параметр**: `go_to('На крыше')` при `fn go_to(name: obj)`
  компилируется в `go_to(_'На крыше')` (имя с пробелом); однословное имя
  строкой — ошибка, пишите голым: `have телефон`, `w ^ имя`;
- **no-paren вызов с одним параметром останавливается на операторе**:
  `have карточка and not type_done` → `have(карточка) and not ...`.
  Если минимальное значение не подходит по типу, аргумент парсится как
  выражение целиком;
- **`event`-параметр принимает голое имя события**: `xaction(Wear, s)`
  → `xaction('Wear', s)`; неизвестное событие — ошибка (`Wearr`).
  События — стандартные плюс объявленные в `event`/`verb`;
- сравнение `event`-значения — тоже без кавычек: `ev == Exam`,
  `event() == Exam` (правый операнд проверяется по списку событий);
- `str`-параметр ожидает именно строку; передача объекта (`_'имя'`) —
  ошибка;
- параметры необязательны: в `on:` — `s, w, wh` (`Any`/`Default` —
  `s, ev, w`), у обработчиков `verb` — `s, w, wh`, у полей объекта — из
  `FIELD_PARAMS` или `s`;
- `use имя` работает в `on:`, в ключах с префиксом (`before Default:`),
  в полях (`daemon: use x`), у глаголов (`on`/`before`/`after`) и в
  `talk:` (`do: use x`);
- все `fn` эмитятся в начало файла (хойстинг), порядок объявления
  не важен;
- `use имя` проверяет, что у `fn` не больше параметров, чем передаёт
  событие (`s, w, wh` / `s, ev, w`); неизвестное имя — ошибка.

Типы у обработчиков событий и полей задаются автоматически:
`s`/`w`/`wh` — `obj`, `ev`/`to` — `str`, `load` — `bool`; глобальные
переменные (`global:`/`const:`) типизируются по начальному значению
(число → `num`, `true/false` → `bool`, `[[...]]` → `str`).

## Стандартная библиотека

`include: stdlib` подключает `extra/mise/stdlib.mise`:

| fn | сигнатура | смысл |
|---|---|---|
| `here` | `() -> obj` | текущая комната |
| `player` | `() -> obj` | игрок (`me()`) |
| `has` | `(obj, attr) -> bool` | `s:has` |
| `hasnt` | `(obj, attr) -> bool` | `s:hasnt` |
| `move` | `(obj, obj)` | `move(s, where)` |
| `attr` | `(obj, attr)` | `s:attr` |
| `inside` | `(obj, obj) -> bool` | `w:inside(x)` |
| `walk` | `(obj)` | `walk(where)` |
| `walkin` | `(obj)` | `walkin(where)` |
| `compass_dir` | `(obj) -> direction?` | `mp:compass_dir` |
| `once_tag` | `(obj, str) -> bool` | `s:once(tag)` |
| `once` | `(obj) -> bool` | `s:once()` |
| `take` | `(obj)` | `take(w)` |
| `drop` | `(obj)` | `drop(w)` |
| `content` | `(obj)` | `mp:content(w)` |
| `inv` | `() -> tbl` | `inv()` |
| `len` | `(tbl) -> num` | длина (таблицы/списка) |
| `pairs` | `(tbl)` | `pairs(t)` (для `for … in`) |
| `ipairs` | `(tbl)` | `ipairs(t)` |
| `walkout` | `()` | `walkout()` |
| `visits` | `(obj) -> num` | `visits(w)` |
| `event` | `() -> event?` | `mp.event` |
| `rnd` | `(...) -> num` | `rnd(...)` |
| `xaction` | `(event, obj)` | `mp:xaction` |
| `daemonStart` | `(obj)` | `DaemonStart(w)` |
| `daemonStop` | `(obj)` | `DaemonStop(w)` |
| `enable` | `(obj)` | `enable(w)` |
| `disable` | `(obj)` | `disable(w)` |
| `place` | `(obj)` | `place(w)` |
| `isDaemon` | `(obj) -> bool` | `isDaemon(w)` |
| `disabled` | `(obj) -> bool` | `disabled(w)` |
| `seen` | `(obj) -> obj?` | `seen(w)` |
| `say` | `(str, ...)` | `p(...)` |
| `line` | `(...)` | `pn(...)` |
| `append` | `(str, ...)` | `pr(...)` |

Игровые обёртки удобно добавлять в `stdlib.mise` по мере надобности.
`include: stdlib` также добавляет пустой объект `none` — заглушку
«ничего» для объектных переменных (`local o = none`), невидимую парсеру
(имя занято: своё `obj none:` объявить нельзя).
Таблицы приходят из `fn ... |lua` (тип `-> tbl`) или полей-таблиц:
типовой идиом — `local t = tbl3`, затем `say t[rnd(len(t))]`.

`include: stdlib` также подключает класс `Path` — проходимый объект-переход
(слова + `walk_to`):

```
Path путь_зала:
  words: зал
  walk_to: зал
```

И класс `Door` — двусторонняя дверь, соединяющая две комнаты (наследует
движковую `door`: enterable/openable, вход по `идти в ...`):

```
Door калитка:
  words: калитка,дверь
  from: улица
  to: дом
  found_in: улица, дом
```

`from`/`to` — комнаты (входную/выходную выбирает текущая комната);
дверь открыта по умолчанию — `attrs: ~open` делает её закрытой
(открывать/закрывать можно: класс наследует `openable`).

## Классы

```
class Prop:
  attrs: scenery
  Default(s, ev): |
    say Тебе нет дела.

class Title(cutscene):
  attrs: noprompt
  Default(s, ev): |
    ...

Prop дерево:
  words: дерево
```

- `class Имя:` → `Имя = Class { ... }`; `class Имя(база):` →
  `Имя = Class({ ... }, база)` (база — Lua-идентификатор: `cutscene`,
  `room`, `dlg`, …);
- классы поддерживают те же поля: `words`, `attrs`, `on`/`before`/`after`/
  `post`, `var`, `with`, произвольные обработчики;
- **экземпляр класса** — декларация с именем класса в роли вида
  (`Prop дерево:`, `Sky небо:`); обрабатывается как `obj`;
- составные имена свойств (`life_Give,Show`, `['n_to,ne_to,...']`)
  компилируются в ключ-скобку `["life_Give,Show"] = ...`;
- `words:` может быть сырым выражением: ``words: `function(s) ... end` ``;
- `words:` может быть списком: каждый элемент — группа синонимов (`,`),
  между элементами ставится `|`:

```
words:
  - труп,мертвец
  - фигура
  - пальто
```

→ `-"труп,мертвец|фигура|пальто"`.

## setup

```
setup:
  dsc: [[^Текст заставки]]
  fmt: dash, quotes
  take: suit, lamp
  hero:
    words: я/мр,1л
    description: Ты -- астронавт.
    on:
      LetGo: Не разбрасывайся вещами.
  on:
    Walk: |
      ...
    Jump: В невесомости это невозможно.
  init: |
    music 'theme.ogg'
    set_autoplay(true)
```

- `take` — объекты, которые выдаются в `init()`;
- `hero` — поля игрока (`pl.*`): `words` → `pl.word = -"..."`,
  `on` → `pl.before_*`;
- `on` — обработчики `game.before_*`;
- `game` — поля объекта `game` (например, `hint_verbs`);
- `init` — тело `init()` (логика или `|lua`);
- `start` — тело `start(load)`.

## patch

```
patch @compass:
  on:
    Default(s, ev): |
      if mp.event ~= 'Drive' and mp.event ~= 'Walk':
        pass

patch game:
  hint_verbs: { "#Exam", "#Walk" }
```

`patch объект:` назначает обработчики (`on`/`before`/`after`/`post`,
отдельные события) и поля (`hint_verbs`, `x`, …) уже существующему
объекту: `_'объект'.before_Default = ...`, `_'game'.hint_verbs = ...`.
Поле `dict: { ... }` даёт словарные формы: `_'game':dict { ... }`
(в т.ч. `patch game: dict: ...`).

## verb

```
verb Tune:
  words: [на|под]строить,смен/ить
  patterns:
    - {noun}/вн : Tune
    - частоту|канал : Tune
  prio: 1

event Tune:
  on: |
    ...
```

- `tag` — тег (по умолчанию `#Имя`), `tag: false` — без тега;
- `words`, `patterns`, `prio`, `hint`;
- действия и обработчики события объявляются отдельно, в `event Имя:`
  (`on:` → `mp.Имя`, `before`/`after` → `mp.before_/after_Имя`);
  `on`/`before`/`after` внутри `verb` не поддерживаются;
- имя события должно быть объявлено (`event`) или быть стандартным.

## event (события и их действия)

```
event Reflect:
  on: |
    ...

event Say:
  before: Сообщить, что предмет пуст.
```

- `event Имя:` регистрирует событие; имя — CamelCase;
- `on:` — реализация действия (`mp.Имя = function(s, w, wh) ...`);
- `before`/`after` — `mp.before_Имя` / `mp.after_Имя`;
- пустое объявление просто регистрирует имя события (для `verb`,
  `before`/`after`-ключей и т.п.); объявляйте событие до/независимо
  от `verb` — `verb` теперь только слова и паттерны.

## extend (расширение существующих глаголов)

```
extend #Take:
  words: выкрасть

extend #Exam:
  patterns:
    - {noun}/вн {noun}/тв : Reflect
```

- со `words:` → `VerbExtendWord` (добавляет слова/шаблоны);
- только `patterns:` → `VerbExtend` (добавляет шаблоны-дескрипторы,
  слова остаются от исходного глагола);
- поддерживаются `prio`, `hint`.

## type (перечисления)

```
type attr: ~, alive, animate, broken, worn

extend type attr: coded, fed
```

(ведущий `~` — разрешить отрицания, см. ниже)

- значения — голые имена (через запятую или `-`-списком); кавычки запрещены;
- `type` без значений и повторный `type` с тем же именем — ошибка;
- `extend type` неизвестного типа — ошибка (защита от опечатки в имени типа);
- проверяются литералы в слотах `fn` с этим типом, `attrs:`,
  `has`/`hasnt`/`attr`, а также в сравнениях `==`/`~=` (если одна
  сторона — выражение этого типа, литерал другой сверяется со списком);
- первый элемент `~` включает отрицание: `~X` разрешён, если `X` —
  допустимое значение (у `attr` включено); без `~` префикс отвергается —
  это позволяет типам вообще не иметь дела с отрицаниями (литеральное
  значение вида `~X` можно перечислить в списке как есть);
- базовые `attr` (атрибуты, с отрицанием) и `direction` (`n_to`, `ne_to`,
  ..., `out_to`) объявлены в `stdlib.mise`; игры расширяют их через
  `extend type ...`.

Тип — это обычная строка: проверка происходит только на сборке, в Lua
эмитится строковый литерал.

## talk (диалоги)

```
talk Разговор_с_Мариной:
  intro: [[-- вступление (необязательно)]]
  option:
    when: q1 == 1
    ask: Что тут случилось?
    reply: -- Какой-то взрыв...
    option:
      ask: Что с регенератором?
      reply: -- Работает...
    option:
      ask: Как с кислородом?
      reply: -- Запасов часов на пять...
      option:
        ask: Хватит, Марина!
        do: |
          say Я взял за плечо девушку...
          walkout()
          q1 = 2
  option:
    always: true
    ask: Я скоро вернусь.
    do: |
      say -- Хорошо, я поищу ещё баллоны...
      walkout()
  label дальше:
    say: -- продолжение...
    option:
      ask: ...
```

Поля фразы:

| Поле | Смысл |
|---|---|
| `ask:` / `say:` | текст варианта (`dsc`) |
| `reply:` | ответ при выборе (текстовый `act`) |
| `do:` | действие (`act`-функция; логика или `|lua`) |
| `when:` | условие доступности (`cond`) |
| `always: true` | не закрывать фразу после выбора |
| `hidden: true`, `only: true` | как в phr |
| `goto: имя` | переход `next = '#имя'` |
| `label имя:` | фраза-метка (вне дерева, крепится к dlg) |
| `option:` (вложенно) | дочерние варианты |

Вложенные `option:` — дерево; `reply:` + `do:` вместе дают функцию, которая
сначала печатает ответ, затем выполняет действие. Компилируется в обычный
`dlg { phr = {...}; obj = { <метки> }; }`, метки ищутся движком по `#имени`.

## Генерация

- отступ — 2 пробела; между top-level блоками и вложенными декларациями —
  пустая строка;
- слова объектов генерируются как `-"..."`, поэтому словарь компилируется
  как обычно (`dict.mrd`);
- многострочные `[[...]]` не переотступаются (сохраняется текст);
- проверки на этапе компиляции: неизвестные события (регистр важен),
  дубли обычных имён (кроме `#тегов`), ссылки на необъявленные объекты
  (`with`/`found_in`/`take`), неизвестные имена/функции/методы внутри
  `|`, типы аргументов и `return` у `fn`, `words` обязателен для
  объекта.

## Ошибки времени компиляции

Всё проверяется до запуска; сообщение указывает место (`logic:N: ...`
для логики, `<объект>.<поле>: ...` для полей). `say`-фолбэк на сырой
текст срабатывает только на ошибках разбора — типовые ошибки
пробрасываются.

**Имена и ссылки**

- кавычки в именах деклараций, тегах, `attrs:`, событиях, значениях
  `type`/`extend type`, элементах списков — ошибка; имена — без
  пробелов и дефисов, `nam:` запрещён (имя = имя декларации);
- дубликаты обычных деклараций запрещены (совпадать могут только теги);
- `with`/`inside`/`found_in` и поля-ссылки (`n_to`, `door_to`,
  `talk_to`, …) ссылаются на объявленные объекты; динамические цели
  задаются через `|lua`/бэктик;
- голые значения в обычных полях объектов/классов обязаны быть
  объектом, событием или значением перечисления (строки — в кавычках);
  в `patch`/`hero`/`setup` поля пока остаются строками (не проверяются);
- объекты в логике — только голым именем: `_'...'` и строки в
  `obj`-слоте — ошибки;
- неизвестные имена/объекты/события/функции; `use` неизвестной или
  inline-функции; вызов метода, не объявленного как `fn`.

**Функции**

- сигнатура: неизвестный тип, `...` не последним, неверное имя
  параметра, дубликат `fn`, отсутствие `|`/`|lua`-тела;
- тело-выражение: `;`, `...`, `fn_` и повтор параметра запрещены;
- вызовы: арность (точная, у вариадических — минимум), типы
  аргументов, `fn` без `()` в позиции значения, отсутствие получателя
  у метода, `...` в логике, вызов поля/выражения.

**Типы**

- несовпадение типов в аргументах, `return`, присваиваниях;
- `any` не проходит в конкретный тип (аннотируйте источник:
  `fn ... -> T`, параметр, поле-литерал);
- `T?` нельзя использовать там, где ждут `T` (методы, `obj`-параметры)
  без сужения (`if o:`); `nil`-тип и смена типа локальной или поля —
  ошибка;
- перечисления: пустой `type`, дубликат, `extend type` неизвестного
  типа, кавычки/пробелы в значениях, неизвестное значение (с
  подсказкой `did you mean`), `~` без `negate`;
- `attrs:` и литералы `attr`/`has`/`hasnt` проверяются по типу `attr`.

**Синтаксис логики**

- табличные конструкторы `{}` и анонимные функции — только через
  `fn ... |lua`; `^` запрещён (объекты — `==`); `#` — только `#тег`
  (длина — `len()`);
- недопустимый lhs присваивания, неизвестное ключевое слово, неверный
  `for` (заголовок или границы не `num`), незавершённые строки/скобки,
  неожиданные отступы.

**Структура файла**

- неизвестные секции/декларации (`events:` больше нет);
- `extend` — только с голым `#Tag`; `patch` — с голой целью;
- `verb` не принимает `on`/`before`/`after` (действия — в `event`);
  `event` — только блок с полями `on`/`before`/`after`;
- `dict:` и `patch ... dict:` — только табличный литерал `{...}`;
- `setup` — известные ключи, `start` — `|`-блок; `type`/`extend type` —
  значения-имена без кавычек; `talk` требует имени; `include` должен
  существовать.

Не проверяется (только рантайм): значения полей (`s.field` — `any`) и
цель `patch`.

## Ограничения

- `dlg` можно писать «сырым» `phr`-литералом, если структура не подходит
  под `talk:`;
- `|lua` / `lua:` остаются escape hatch для всего, что не покрыто DSL
  (внешние include, `game:dict`, нестандартные функции);
- комментарии из `.mise` в сгенерированный Lua не переносятся.

Полные примеры:
- `tests/mise-cloak/game.mise` и `tests/mise-cloak-en/game.mise` —
  эталонные демо (`lang: ru`/`en`), ноль `lua`-блоков в логике;
- `tests/mise-heidi/game.mise` — минимальная игра с `ending`;
- `tests/mise-wtell/game.mise` — классы, события, `dict`, `setup.init`
  (один `lua:` — настройки движка);
- `tests/mise-alice/game.mise` — классы с демонами (`rnd`), поля-ссылки
  с `_(...)`, `extend #Exam`.

Все игры гоняются `tests/run-mise-tests.sh` (сверка Lua и, с
`--engine`, транскриптов оригинал/конверсия).
