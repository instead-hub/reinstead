# mise — спецификация DSL

`extra/mise/mise.py` — транспайлер декларативного DSL (`.mise`) в обычный
Lua для INSTEAD/МЕТАПАРСЕР 3. На выходе — стандартный `main3.lua`
(или `main3-ru.lua` / `main3-en.lua`), который можно запускать без Python.

```
python3 extra/mise/mise.py game.mise -o main3.lua
```

## Структура файла

Файл состоит из секций и деклараций:

```
name: Судный день
version: 0.1
author: Пётр Косых
info: Короткая зарисовка об одиноком космонавте.
lang: ru
fmt: dash, quotes
require: snd

const:
  ...

global:
  ...

setup:
  ...

impl объект:
  ...

fn имя(параметр: тип, ...) -> тип1, тип2:
  ...

obj имя:
  ...

room имя:
  ...

talk Диалог:
  ...

verb Имя:
  ...

remove #Tag:
  # снимает глагол (см. «verb»)

lua:
  |lua
  -- аварийный выход: произвольный Lua в этом месте
```

- `name/version/author/info` — метаданные (`--$Name:...$` и т.п.).
- `lang: ru|en` — какая языковая прослойка подключается (`parser/mp-ru`/`mp-en`).
- `fmt: dash, quotes` — флаги `fmt.*`.
- `require: snd` — дополнительные `require`.
- `include: stdlib` — подключить общую библиотеку `fn` (см. ниже);
  если рядом есть `<имя>-<lang>.mise` (`stdlib-ru.mise`), берётся он.
- `event Имя:` — объявление события (и, при желании, его действия, см. ниже).
- `const:` — объявления `const 'имя' (значение)` (read-only, не сохраняются).
- `global:` — объявления `global 'имя' (значение)` (сохраняются в сейвах).
- `setup:` — мир/игрок/общие обработчики (см. ниже).
- `impl объект:` — правка существующего объекта/модуля (`@compass`, `game`).
- `fn имя(параметр: тип, ...) -> тип1, тип2:` — именованный кусочек/обработчик (см. ниже).
- `type имя: значения` — перечисление (см. ниже).
- `extend type имя: значения` — расширить перечисление.
- `remove #Tag:` — снять глагол (см. «verb»).
- `lua:` — вставка произвольного Lua (escape hatch).

Имена и теги (`obj имя:`, `room #зал:`, `impl game:`, `extend #Take:`),
события, `attrs:` и элементы списков пишутся **голыми** — кавычки в них
запрещены (ошибка компиляции). Строковые значения остаются как были:
тексты, `words:`, `say '...'`.

Отступы — пробелы (таб = 3); вложенность задаётся отступом. Пустые строки
игнорируются. Комментарий — `#` в начале строки или отдельным словом
(окружённый пробелами).

## Значения (типизация литералами)

Тип значения задаётся формой записи:

| Литерал | Тип |
|---|---|
| `[[...]]`, `[==[...]==]` | строка (может быть многострочной) |
| `"..."`, `'...'` | строка (однострочная) |
| `2`, `-1`, `3.14` | число |
| `true`, `false`, `nil` | булево/nil |
| `{ ... }`, `[ ... ]` | табличный литерал (Lua), читается до баланса скобок |
| `` `expr` `` | сырое Lua-выражение (вставляется дословно) |
| голый текст | см. правила ниже |

Голые значения:

- в «текстовых» ключах (`description`, `dsc`, `title`, `inv`, `words`,
  `text`, `when_*`, `cant_go`, `ask`, `reply`, `say`, `intro` и т.п.) и в
  значениях обработчиков — это **текст** (становится `[[...]]`); запятые и
  прочие символы — часть текста;
- в остальных местах — либо **ссылка на объект** (если совпадает с
  объявленным id → `_'id'`), либо строка (если id не объявлен);
- списки через запятую (`attrs: worn, clothing`, `with: gate, lever`)
  разбираются как список значений;
- табличные литералы (`{...}`/`[...]`) распознаются в нетекстовых
  ключах — например, `phr: { ... }`, `hint_verbs: { "#Exam" }`;
- значение занимает всю строку: после закрытой формы (`"..."`, `[[...]]`,
  `` `...` ``, `{...}`) допустимы только пробелы и `#`-комментарий —
  иначе ошибка `unexpected text after value`. Если нужен текст с
  кавычками и припиской, берите Long (`description: [[«…» — читаешь
  ты…]]`) или логику (`description: |` + `say`);
- списки строк/шаблонов — через `-`-пункты (элемент может быть Long,
  например страницы `text:` — `- [[...]]`):

```
  patterns:
    - {noun}/вн : Tune
    - частоту|канал : Tune
```

## Типы полей и переменных

Поля объектов типизируются по литеральному значению объявления
(`числа` → `num`, `true/false` → `bool`, строки → `str`, `{...}` → `tbl`,
`nil` → `nil`, `&fn`/`|`/`|lua` → `fn`), а у prop с альтернативой
`fn(...)` — сигнатура пропа (`description: |` → `fn(obj)->str`,
`talk_to: &f` → `fn(obj)->obj`); у классов поля наследуются, у
экземпляров — дополняются своими. Тип известен для прямых ссылок
(`key.num`, `pole.has_been_saluted`), не для `s.field` с параметром.

Голое значение в поле — это **имя-символ**, а не строка. Порядок:
объявленный объект → тип `obj`; известное событие → `event`; значение
объявленного перечисления → его тип; иначе — ошибка («unknown name …
in field …»). Строки пишутся явно: `[[...]]`/`"..."`. То же правило
сверяется в полях `impl`, `setup`/`hero`/`game` и значениях
`const`/`global` (там проверяется имя, а тип переменной берётся из
начального значения).

Для `obj` в объявлении остаётся строка-имя (движку она и нужна), а
**чтения оборачиваются в `_(...)`** — движок резолвит имя в объект в
рантайме (ср. `ini` в оригинале). Поэтому forward-ссылки на объявленные
позже комнаты/объекты безопасны. Явный объект (`_'имя'` в бэктиках)
резолвится сразу и не оборачивается.

`s.field` типизируется по полям владельца и внутри тел объектов, и
внутри классов (owner-контекст); у безымянных объектов и для
неизвестных полей тип остаётся `any`.

Поля-ссылки (`n_to`, `door_to`, `talk_to`, `with_key`, `found_in`,
`scope`, `from`/`to` класса `Door`, …) типизированы в `stdlib.mise`
секцией `props:` (`ref`, `tbl[ref]`, `list`); их значения (в т.ч. списки)
сверяются с объявленными объектами. Свои ref-поля добавляются `extend refs:
custom_to` (без типа). Без `include: stdlib` встроенных props/refs нет.

Локальные переменные: `local x` (без значения) и `local x = nil` —
«без типа» (`any`); первое конкретное присваивание фиксирует тип, все
следующие обязаны быть совместимыми (`local x = 1; x = 'a'` — ошибка).
Переменная «obj или nil» берётся из `?`-источника (`local o = where(x)`)
или параметра `o: obj?`: тогда допустимы и `o = obj`, и `o = nil`.
Смена типа поля (`key.flag = 1` при `flag: false`) — ошибка.

## nil и optional-типы (`T?`)

- `nil` — отдельный тип; `T?` — «`T` или `nil`» (например `obj?`).
- Совместимость односторонняя: `obj` можно туда, где ждут `obj?`, но
  `obj?` в `obj` — ошибка; методы, `obj`-параметры, поле и индекс
  (`o.field`, `o[1]`) требуют не-nil («expected obj, got obj?»).
- результат `and`/`or` — значение одного из операндов (как в Lua),
  поэтому тип — сохранившаяся часть левого плюс правый: `and` оставляет
  «ложную» часть (`nil` у `T?`, `false` у `bool`), `or` — «истинную»
  (без `nil`); сам `bool` остаётся `bool` (типов `true`/`false` нет).
  Так `x or none` и `x and x or none` для `x: obj?` дают `obj`, а
  `cond and [[да]] or [[нет]]` — `bool|str` (для строк пишите `if`);
- Сужение в `if` (простые условия по имени, в т.ч. цепочки через `and`
  и короткое замыкание `or`):
  - `if o:` / `if o ~= nil:` → в ветке `o: obj`;
  - `if o == nil:` / `if not o:` → в ветке `o: nil`;
  - в `a or b` часть `b` видит сужение от «`a` ложно», поэтому
    `if not o or o.field:` — ок;
  - у одиночного `if` с `else` ветка `else` получает обратное сужение.
- После `if` сужения нет; объявляйте `local o = ...` и работайте в ветке.
- Union-типы: `T|U` — значение подходит, если подходит под любую
  альтернативу (`str|num`). Канонический вид: альтернативы сортируются,
  `nil`/`?` поднимаются в один хвостовой `?` (`str|num?` ≡ `num?|str` ≡
  `num|str?`).
- Параметры `fn` с optional-типом можно не передавать, но только
  хвостовые: обязательный параметр после optional — ошибка. Пример
  (stdlib): `fn noun(s: obj, n: tbl[case|gram]|case|num?, nn: num?)
  -> str` — допустимы `noun()`, `w:noun 'вн'`, `w:noun('вн', 1)`; arity-диагностика таких fn —
  `expects 0..2 argument(s)`.
- Пример: `fn seen(w: any) -> obj?` (stdlib):

```
local o = seen 'ключ'
if o:
  o:attr 'open'      # ок, o сужен до obj
o:attr 'open'        # ошибка: возможно nil
```

## Декларации

```
obj        — обычный объект (декорация — `attrs: scenery`)
room       — комната
door       — дверь
story      — cutscene
ending     — gameover
talk       — диалог в DSL (см. ниже)
verb       — глагол
class      — класс (Class { ... }, см. ниже)
mixin      — набор обработчиков/полей (см. ниже)
props      — типы движковых свойств (см. «Свойства»)
refs       — поля-ссылки (см. «Типы полей»)
Имя        — экземпляр класса (любой вид: `Path x:`, `path x:`)
```

Идентификатор: `obj ключ` или `obj "имя с пробелами"`. Имя декларации —
это и есть имя объекта в движке (`nam`), отдельного поля `nam:` нет.
Повторяющиеся имена допустимы **только для тегов** (`obj #окно:` в разных
комнатах); два обычных `obj кухня:` — ошибка компиляции. Имя можно не
указывать (`obj:`, `room:` и т.п.) — тогда `nam` не задаётся
(автоименованный объект).

Общие поля:

| Поле | Смысл |
|---|---|
| `words: скафандр,сумка\|мешок` | словарные слова → `-"..."`; список из строк даёт алиасы через `\|` (`,` внутри строки — синонимы) |
| `word: \|` | динамические слова: `append ...`/`say ...` (`-"..."` — no-op) |
| `attrs: worn, clothing` | атрибуты → `:attr '...'` |
| `dict: { ["форма/п"] = "текст" }` | словарные формы → `:dict { ... }` |
| `disabled: true\|false` | `:disable()`; `false` — ничего (в `impl` — `:enable()`) |
| `on X:` | метод события: `X = function(s, w, wh)`; `on Open, Close:` → `["Open,Close"]` (у `Any`/`Default` — `s, ev, w`) |
| `before/after/post/life X:` | `before_X`/`after_X`/`post_X`/`life_X`; событие без фазы — ошибка |
| `with:` | вложенные декларации (`obj:`/`obj имя:`) **или** список ссылок (`with: имя, имя`); определения и ссылки совмещаются двумя ключами `with:` (ссылки эмитятся первыми) |
| `found_in: room1, room2` | где появляется объект |
| `n_to/e_to/...`, `in_to`, `out_to`, `u_to`, `d_to` | переходы (значение — комната, дверь или логика/функция) |
| `door_to`, `next_to`, `talk_to`, `with_key` | как в API |
| `description`, `dsc`, `title`, `inv`, `when_open`, … | текст/логика/Lua |
| `daemon`, `each_turn`, `when_open`/`when_closed`/`when_on`/`when_off`, `found_in`, `door_to` | обработчики-поля `(s)` |
| `compass_look` | обработчик `(s, to)` (направление) |
| `scope` | список объектов или обработчик `(s, w)` |
| `enter`/`exit`, `onenter`/`onexit` | обработчики STEAD3 `(s, w)` (откуда/куда) |
| `default_Event`, `capacity`, `help`, `disp`, `gfx`, `word`/`raw_word` | простые свойства (типы — в `props:`) |
| `text:` | текст cutscene: одна строка/`[[...]]`, страницы — `-`-список или fn(s, n) |

`scope` задаётся списком объектов (`scope: ключ, лампа` — голые имена,
сверяются по `refs:`) или обработчиком (`scope: |`, `scope: |lua` — в
движке вызывается как `function(s, w)`, `w` — список доступного;
наполнять его удобно в `|lua`: `w:add(_'лампа')`).

Обработчики:

```
obj камень:
  on Take: Куда мне его.
  after Put: |
    say Ты положил камень.
    stop
  on Enter, Climb: |
    wear_item(s)
  before Pull, Transfer: |lua
    ...
  with: рычаг
  with:
    obj ядро: ...
```

- фаза — первое слово ключа: `on` — **метод события** (основная фаза,
  `Take = function(s, w, wh)`; у `Any`/`Default` — `s, ev, w`),
  `before`/`after`/`post` — `before_X`/`after_X`/`post_X`, `life` — `life_X`
  (реплики персонажей);
- ключ — имя события **точно как в движке** (`Take`, `Enter`, `SwitchOn`,
  `Any`, `Default`); нижний регистр не допускается; фаза обязательна
  (`Take:` без фазы — ошибка), блока `on:` нет;
- несколько событий в одном ключе (`on Enter, Climb:`) для объекта
  компилируются в один комбинированный ключ движка
  `["Enter,Climb"] = ...` (как в оригинальных играх); для
  `pl.`/`game.`/`impl` — в отдельные поля;
- значение — одна строка текста, `pass` (обработчик `return false`),
  блок `|` (чистая логика), `|lua` (Lua) или `&имя`
  (ссылка на именованный `fn` или Lua-функцию);
- параметры можно задать явно — только именами: `on Default(s, ev, w):`,
  `before Take(s, w):`; типы в ключе (`before Cut(s, w: obj?)`) запрещены —
  они берутся из `type event:` (или `props:` для полей).

## Логика (`|`)

Блоки логики и Lua задаются маркером `|`/`|lua`; конец — по отступу
(отдельная закрывающая строка не нужна). Форма с закрывающим `~~~` удалена.

```
include: stdlib

Take: |
  say Ты взял камень.
  line
  append !!!
  stop

fn here() -> obj: |lua
  return here()
```

Операторы (по одному в строке, вложенность отступами):

| Оператор | Lua |
|---|---|
| `say ...`, `line`, `append ...` | вызовы `fn say/line/append` |
| `stop` / `pass` | `return` / `return false` |
| `return expr` | `return expr` |
| `x = expr`, `x += expr`, `x -= expr` | присваивание |
| `if cond:` / `elseif cond:` / `else:` | `if ... then ... end` |
| `when cond:` / `when cond:` / `default:` | то же (`if/elseif/else`) |
| `for header:` | `for ... do ... end` (границы — `num`; переменные можно
аннотировать: `for _, w: obj in ipairs(t):`) |
| `local a, b = ...` | локальные переменные |
| `break` | выход из цикла |
| вызов `f(...)` (fn) или присваивание | оператор |

`when cond:` — то же, что `if`, но цепочка читается в cond-стиле:
продолжения — `when`, «иначе» — `default:`.

```
fn kind(s: obj) -> str: |
  when s:isa Tree:
    return [[дерево]]
  when s:has scenery:
    return [[декорация]]
  default:
    return [[прочее]]
```

В одной цепочке стили не смешиваются: `elseif`/`else` в
`when`-цепочке и `when`/`default` в `if`-цепочке — ошибки; `default:`
без `when` — ошибка.

Ошибки внутри блока логики сообщаются с номером строки (`logic:12`).

`|` — жёсткое подмножество Lua, проверяемое на этапе компиляции:
запрещены `while`/`repeat`/`goto`, анонимные функции, `function`,
длинные операторы вне грамматики. Вызовы движка в `|` запрещены:
разрешены только параметры, локальные, объявленные объекты, глобальные
игры (`global:`/`const:`), вызовы `fn`. Значения
`mp`/`std`/`game`/`pl`, вызовы методов (`s:has`, `s:once`,
`mp:xaction`), чистые функции Lua (`pairs`, `math`, `tostring`, ...) —
ошибка: оборачивайте в `fn`. Литералы-списки `{ e1, e2 }` разрешены и
типизируются как `tbl[T1|T2|...]` (пустой `{}` — `tbl[]`; элементы под
ожидание `tbl[T]` проверяются). Непокрытое — только через `|lua`.

Голые значения перечислений и событий доступны и в логике: значение
резолвится по уникальности (`local m = happy`, `if e == Exam:`);
если значение принадлежит нескольким перечислениям — ошибка
«ambiguous value».

`say`/`line`/`append` — обычные `fn` из `include: stdlib`
(`say(text: str, ...)`, `line()`, `append(text: str)`). Аргумент
`str`-параметра без скобок считается выражением, только если начинается
с кавычки, `(`, `_`, `#`, числа или известного имени; иначе весь текст —
строка. Склейка — через выражение или скобки: `say 'a' .. b`,
`say(a .. b)`, `say it(w), ' x'`.

Переписывание выражений:

- объявленное имя → `_'имя'`; прямо аргументом вызова скобки добавляются:
  `go_to space2` → `go_to(_'space2')`;
- имя-тег: `#окно` → `_'#окно'` (только для объявленного тега; `#`
  больше нигде не поддерживается — длину берите `len(...)`);
- **объекты — только голыми именами**: `obj`-параметр (`have телефон`),
  приёмник метода (`w:move зал`), сравнение (`w == имя`), поля-ссылки
  (`with`, `found_in`, `n_to`/`out_to`/`door_to`/`talk_to`/...) и `return`
  имени объекта (`return Тронный_зал`). Строка, совпадающая с именем
  объекта, — ошибка компиляции; кавычки для объектов не используются
  вообще;
- **`^` запрещён** — сравнение объектов только через `==`;
- **имена объявлений — идентификаторы** (`[#\w]+`, без пробелов/дефисов):
  `room Тронный_зал:`, `obj #глаза_совы:`;
- `str`/`num`/`bool`-параметры проверяются на тип; `obj`-параметр с
  числом/строкой — ошибка.

Что нельзя записать «простым именем» (и почему):
- имена с пробелами/дефисами недопустимы у объектов — переименуйте
  (`Тронный_зал`, `ледяное_пламя`);
- динамические ссылки `_('@'..t)` — остаются вызовом `_`;
- `|lua`/`lua:` не переписываются — там `_'...'` пишется как в Lua.

## fn и ссылки (кусочки кода)

Именованный кусочек описывается вне объекта; на него можно сослаться
по имени (`&имя`) или вызвать из `|`:

```
fn cable_connect(s: obj, wh: obj): |
  if wh ^ 'Вездеход':
    ...

fn move_to(s: obj, where: obj): |lua
  move(s, where)

obj Кабель:
  on Insert, Activate: &cable_connect
```

- `fn имя(параметр: тип, ...) -> тип1, тип2:` — блок `|` (проверяется) или
  `|lua` (небезопасный escape hatch); компилируется в
  `local function fn_имя(параметры) ... end` (префикс `fn_` исключает
  коллизии с движком; вызовы тоже компилируются в `fn_имя`);
- тело-выражение в бэктиках — inline: `fn len(v: tbl) -> num: `#v``
  подставляется в место вызова (в скобках) и не эмитится; параметр не
  должен встречаться больше одного раза, `...` и `fn_` запрещены;
- хвостовой `...` — 0+ аргументов; его можно типизировать: `...: T` —
  каждый хвостовой аргумент проверяется против `T`
  (`fn say(text: str|num|bool|obj|event, ...: str|num|bool|obj|event)`);
  без типа `...` хвост не проверяется;
- типы: `obj` (объект/комната/тег), `str`, `num`, `bool`, `any`,
  `event` (событие движка/игры), `tbl` (таблица), `tbl[T]` (таблица со
  значениями типа `T`; `tbl[any]` ≡ `tbl`), `list` (движковый список
  `std.list` с методами `add`/`del`), имя класса, `fn`
  (значение-функция);
- `tbl[T]`: `tbl[A]` совместим с `tbl[B]`, если `A` совместим с `B`, и с
  `tbl`; `tbl` в `tbl[T]` — ошибка; `tbl[]` (пустой литерал) совместим
  с любым `tbl[T]`; чтение `t[1]` из `tbl[T]` даёт `T`;
- `list`: список совместим с `tbl` (его можно передавать в `len`,
  `pairs` и т.п.), но `tbl` в `list` — ошибка (у обычной таблицы нет
  методов); `{}`-литерал — всегда `tbl`; чтение `w[1]` из `list` даёт
  `obj`; значения типа `list` дают `inv()`, `getDaemons()` и `w` в
  `scope:`-обработчике;
- класс-тип: `fn heavier(s: Box, n: num) -> bool` — в теле `s.field`
  типизируется по полям класса; `&имя` такой fn требует, чтобы владелец
  обработчика был этим классом или его потомком;
- `&имя` — ссылка на функцию: в логике это значение-функция
  (`for_plural(s, &on_take)`), в значении поля/обработчика — сама
  функция (`before Take: &on_take`); inline-фн как значение
  запрещены; вызов `&f(...)` в логике запрещён — только через
  stdlib-функции с колбэком; голое имя `fn` с обязательными параметрами —
  значение только в колбэк-позиции (там, где ожидается `fn`), иначе
  `fn X needs arguments` — нужен вызов (`f(x)`) или `&имя`;
- строгие сигнатуры: тип может быть функцией — `f: fn(w: obj) -> bool`
  (имена параметров необязательны, `fn(w: obj)?` — optional). `&имя`
  сверяется с ожидаемым типом: число аргументов колбэка ≤ ожидаемого,
  типы параметров и возврата; у игровых Lua-функций подпись неизвестна —
  они принимаются как opaque `fn`. Значение `f` типа `fn(T)->R` можно
  вызывать (`f(x)`): аргументы проверяются, результат имеет тип `R`;
  вызов поля/выражения по-прежнему запрещён;
  без аннотации — `any`; возвращаемый тип после `->` (по умолчанию `any`);
  последний параметр `...` делает `fn` вариативной (`fn say(text: str, ...)`);
- **несколько возвращаемых значений**: `fn f() -> num, str:` возвращает
  два; при вызове они раскрываются как в Lua — `local a, b = f()` связывает
  оба, `local x = f()` берёт первое, `return g()` переносит все значения `g`;
  каждое возвращаемое значение проверяется по своему типу; `|lua`-тела и
  inline-выражения могут возвращать несколько значений, inline-функции —
  нет; `&`-сигнатуры колбэков тоже допускают несколько возвратов:
  `f: fn(w: obj) -> num, str`;
- **скобки необязательны**: при одном параметре (`go_to space2`,
  `say привет`) и когда вызов идёт без аргументов — нет параметров
  (`line`, `box:once`, `here.rotate`, `player`) или все они опциональны
  (`empty`, `pop`, `walkback`); `()` можно писать всегда (`line()`,
  `if fn() and fn2()`); у свободного вызова при двух и более параметрах
  скобки обязательны (у `obj:fn` без скобок допускается один хвостовой
  аргумент, см. ниже); голое имя inline-`fn`, которую нельзя вызвать без
  аргументов, — ошибка `fn X must be called with ()`;
- такие вызовы без аргументов в выражениях делаются автоматически
  (в т.ч. перед `.`/операторами): `here.rotate` → `fn_here().rotate`;
- **`str`-параметр забирает сырой текст**: `music theme.ogg` — это
  `fn_music([[theme.ogg]])`, кавычки не нужны; выражение — если аргумент
  начинается с кавычки, `(`, `_`, `#`, числа или известного имени
  (`say 'a' .. b`, `say it(w), ' x'`);
- `obj:fn(аргументы)` — синоним `fn(obj, аргументы)`: `box:has('open')`
  → `fn_has(_'box', 'open')`, `here():hasnt('open')` тоже работает;
- `obj:fn { ... }` и `fn { ... }` — таблица-литерал как единственный
  аргумент (как в Lua): `s:noun { рд, 2 }` ≡ `s:noun({ рд, 2 })`,
  `first_str { [[a]], [[b]] }` ≡ `first_str({ [[a]], [[b]] })`;
- без скобок — ровно один хвостовой аргумент-имя; как оно развернётся,
  решает тип второго параметра: `str` — сырой текст (`radio:hasnt on`
  → `fn_hasnt(_'radio', [[on]])`, `s:attr ~on` → `fn_attr(s, [[~on]])`);
  перечисление — голое значение (`s:has light`); `event` — имя события;
  `obj` — имя объявленного объекта (`player:move foyer`,
  `box:inside container`); иначе — переменная/глобал/нуль-арная `fn`,
  а неизвестное имя — ошибка;
- выражения в хвосте без скобок не принимаются (кроме таблицы
  `{ ... }`) — нужны `()`: поле
  `s:has s.xxx` — ошибка (`s.xxx` не литерал), правильно `s:has(s.xxx)`;
  числа/склейка/индексы — тоже только в скобках; без аргументов —
  `box:once` или `box:once()`;
- в `|`-теле `fn` операторы `return`/`pass`/`stop` проверяются на
  соответствие `-> тип` (включая вложенные `if`/`for`); `pass` — это
  `bool`, `stop` — `nil`;
- вызов из `|` проверяется: арность и типы аргументов, тип результата
  участвует в дальнейших проверках (`random(n: num) -> num` можно
  складывать, `str` — нет);
- **`obj`-параметр**: `go_to('На крыше')` при `fn go_to(name: obj)`
  компилируется в `go_to(_'На крыше')` (имя с пробелом); однословное имя
  строкой — ошибка, пишите голым: `have телефон`, `w ^ имя`;
- **no-paren вызов с одним параметром останавливается на операторе**:
  `have карточка and not type_done` → `have(карточка) and not ...`.
  Если минимальное значение не подходит по типу, аргумент парсится как
  выражение целиком. Если остаток не парсится как выражение, а параметр
  принимает `str`, он молча становится строкой (`append turnout:noun им`
  печатает текст, а не склоняет) — для вызова ставьте скобки:
  `append(turnout:noun(им))` или `append (turnout:noun(им))`;
- **`event`-параметр принимает голое имя события**: `xaction(Wear, s)`
  → `xaction('Wear', s)`; неизвестное событие — ошибка (`Wearr`).
  События — стандартные плюс объявленные в `event`/`verb`;
- сравнение `event`-значения — тоже без кавычек: `ev == Exam`,
  `event() == Exam` (правый операнд проверяется по списку событий);
- `str`-параметр ожидает именно строку; передача объекта (`_'имя'`) —
  ошибка;
- параметры необязательны: в обработчиках — `s, w, wh` (`Any`/`Default` —
  `s, ev, w, wh`), у обработчиков `verb` — `s, w, wh`, у полей объекта —
  из `props:` (`fn`-тип) или `s`;
- `&имя` работает в обработчиках (`on Take:`, `before Default:`),
  проверяя арность, типы параметров (по выведенному env обработчика:
  `s`/`w`/`wh`, сигнатура события, сужение `ev == X`) и (для класс-типа
  первого параметра) владельца;
  в полях (`daemon: &x`), у глаголов (`on`/`before`/`after`) и в
  `talk:` (`do: &x`); помимо DSL-`fn` можно сослаться на функцию из
  `lua:`/подключаемого Lua-файла — у неё подпись неизвестна, проверок нет;
- все `fn` эмитятся в начало файла (хойстинг), порядок объявления
  не важен;
- `&имя` проверяет, что у `fn` не больше параметров, чем передаёт
  событие (`s, w, wh` / `s, ev, w`), что типы её параметров совместимы
  с env обработчика и (у полей с возвратом) что возврат подходит;
  неизвестное имя — ошибка.

Типы у обработчиков событий и полей задаются автоматически:
`s`/`w`/`wh` — `obj` (уточняются `type event:`/`props:`), `ev` — `event`,
`to` — `any`, `load` — `bool`; глобальные
переменные (`global:`/`const:`) типизируются по начальному значению
(число → `num`, `true/false` → `bool`, `[[...]]` → `str`, имя объекта →
`obj`, значение перечисления → его тип). `obj`-переменные, как и поля,
хранят имя объекта: чтения оборачиваются в `_(...)`, а запись идёт по
голому имени (`drone_passed = none` → `drone_passed = _'none'`).

## Стандартная библиотека

`include: stdlib` подключает `extra/mise/stdlib.mise` — языково-нейтральную
часть (props/типы/события, инлайн-обёртки, `none`, классы `Door`/`Path`).
Языковой текст классов — в `stdlib-<lang>.mise` (по `lang:` автоматически
подключается `stdlib-ru.mise`/`stdlib-en.mise` через тот же
`include: stdlib`): там `fn way_dsc(s: obj, w: obj) -> str` (дверь ведёт
в `w`), `fn path_dsc(w: obj) -> str` и слова словаря (`--"..."`).

## Свойства (`props:`)

Движковые свойства объявляются в stdlib типизированно:

```
props obj:
  scope: list | fn(s: obj, w: list)
  dsc: str | bool | fn(s: obj) -> str
  default_Event: event | fn(s: obj) -> event
  capacity: num | fn(s: obj) -> num
  gfx: str | fn(s: obj) -> str
  word: str | fn(s: obj) -> str

props room:
  n_to: ref | fn(s: obj) -> ref

props door:
  door_to: ref | fn(s: obj) -> ref

props story:
  text: str | tbl[str] | fn(s: obj, n: num) -> str
```

Так разложены и стандартные пропсы: общие движковые поля — в `props obj:`
(их видят все объекты), направления и `enter`/`exit`/`cant_go`/
`compass_look` — в `props room:`, `from`/`to`/`door_to` — в `props door:`,
`text` — в `props story:`, поля фразы диалога — в `props option:`.

- `ref` — голое имя объявленного объекта (`n_to: зал`); `tbl[ref]` —
  список таких имён; `list` — движковый список имён (`scope: лампа,
  ключ`); `fn(...)` — обработчик (имена параметров дают типы в теле `|`,
  эмитится `function(s, ...)`); `str`/`bool`/`num`/`tbl`/`event` —
  значения как есть.
- `fn(...) -> T` — возврат тела проверяется (`return` должен давать `T`;
  `ref` в теле читается как `obj`); `return`/`stop` без значения, `false`
  и `nil` — «нет значения» и допустимы всегда. Тип в `props:` может быть
  и именем класса (`props Chest: cb: fn(s: Chest) -> bool`).
- Массивы (`tbl`, `tbl[ref]`, `list`) можно писать значением-списком,
  `-`-строками (многострочно) или `{ ... }`:
  `scope: лампа, ключ` ≡ `scope:` + `- лампа`/`- ключ` ≡
  `scope: { лампа, ключ }`. Элементы `tbl[ref]`/`list` — имена объектов
  (голые или строкой), проверяются и эмитятся строками
  (`{ "лампа" }`); `{ ... }`/`[...]` у прочих `tbl` — сырой Lua-escape
  без проверки.
- Скоупы: `props <скоуп>:` объявляет поля конкретных конструкций — виды
  (`obj`, `room`, `door`, `story`, `ending`; `hero`/`game` — для блоков
  `setup:`), имена классов,
  `talk` (сам диалог) и `option` (фраза диалога: `intro`, `ask`, `say`,
  `reply`, `onempty`, `when`). Поиск: скоуп → его движковые родители
  (`option → obj`, `talk`/`story`/`ending` → `room → obj`, `class X(Y)` →
  `Y`) → общий `props:`. Дубликат в одном скоупе — ошибка, одноимённое в
  разных — допустимо (конкретный скоуп побеждает). Неизвестный скоуп —
  ошибка `props scope X: unknown scope`.
- Ошибка, если значение не подходит ни одной альтернативе (`scope: 3`,
  `n_to: 3`, `daemon: [[x]]`, `capacity: | return 'x'`) или `&`-функция
  возвращает не тот тип.
- `ref` — тип только для значений полей (в логике ссылки уже `obj`);
  `props` расширяются играми обычным блоком (дубликаты — ошибка).
- **Поля должны быть объявлены**: в логике читать (`s.x`) и писать
  (`s.x = ...`) можно только то, что где-либо объявлено — поле
  объекта/класса, `props`, `refs:`/`extend refs:` — либо движковое поле
  (`nam`, `tag`, `obj`, `way`, `lifes`), либо имя с `__` (системные и
  динамические значения). Опечатка — `unknown field '...'` (с подсказкой
  `use __...`); запись в движковое поле — `... is an engine field and
  cannot be assigned`. Содержимое `way`/`obj`/`lifes` менять можно
  (`s.way:add(x)`), поля, созданные в `|lua`/бэктиках, проверке не видны.

`say t[rnd(len(t))]` (`t[1]` из `tbl[T]` имеет тип `T`).

`include: stdlib` также подключает класс `Path` — проходимый объект-переход

```

  walk_to: зал
```

И класс `Door` — двусторонняя дверь, соединяющая две комнаты (наследует
движковую `door`: enterable/openable, вход по `идти в ...`):

```
Door калитка:
  words: калитка,дверь
  from: улица
  to: дом
  found_in: улица, дом
```

`from`/`to` — комнаты (входную/выходную выбирает текущая комната);
дверь открыта по умолчанию — `attrs: ~open` делает её закрытой
(открывать/закрывать можно: класс наследует `openable`).

## Классы

```
class Prop:
  attrs: scenery
  before Default(s, ev): |
    say Тебе нет дела.

class Title(cutscene):
  attrs: noprompt
  before Default(s, ev): |
    ...

Prop дерево:
  words: дерево
```

- `class Имя:` → `Имя = Class { ... }`; `class Имя(база):` →
  `Имя = Class({ ... }, база)` (база — Lua-идентификатор: `cutscene`,
  `room`, `dlg`, …);
- имя класса — любого регистра: `class Path:` и `class path:` равнозначны
  (строчное имя даёт вид вида `path тропа:`); зарезервированы имена
  конструкций (`obj`, `room`, `door`, `story`, `ending`, `talk`, `verb`,
  `props`, …) — ошибка `class X: name is reserved`;
- классы поддерживают те же поля: `words`, `attrs`, `on X`/`before`/`after`/
  `post`, `with`, произвольные обработчики;
- **экземпляр класса** — декларация с именем класса в роли вида
  (`Prop дерево:`, `path тропа:`); обрабатывается как `obj`; имя класса
  должно быть объявлено (иначе `unknown kind`);
- составные имена свойств (`life_Give,Show`, `['n_to,ne_to,...']`)
  компилируются в ключ-скобку `["life_Give,Show"] = ...`;
- `words:` может быть сырым выражением: ``words: `function(s) ... end` ``;
- `words:` может быть списком: каждый элемент — группа синонимов (`,`),
  между элементами ставится `|`:

```
words:
  - труп,мертвец
  - фигура
  - пальто
```

→ `-"труп,мертвец|фигура|пальто"`.

## mixin

```
mixin Talkative:
  heard: false
  before Talk: |
    s.heard = true
    say [[поговорили]]

obj parrot:
  words: попугай
  mixin: Talkative
```

`mixin Имя:` — именованный набор обработчиков/полей, сам
ничего не эмитит. Привязка `mixin: A, B` в теле `obj`/класса/`impl`
подставляет ключи mixins **до** собственных ключей, так что свои
ключи перекрывают mixin; одноимённые ключи двух mixins — ошибка.
Поля mixin типизируются и вливаются в поля цели (работает
`s.field`); вложенные mixin (`mixin:` внутри `mixin`) запрещены.
Экземпляры класса наследуют поведение класса через метатаблицу.

## setup

```
setup:
  dsc: [[^Текст заставки]]
  fmt: dash, quotes
  take: suit, lamp
  hero:
    words: я/мр,1л
    description: Ты -- астронавт.
    on:
      LetGo: Не разбрасывайся вещами.
  on:
    Walk: |
      ...
    Jump: В невесомости это невозможно.
  init: |
    music 'theme.ogg'
    set_autoplay(true)
```

- `take` — объекты, которые выдаются в `init()`;
- `hero` — поля игрока (`pl.*`): `words` → `pl.word = -"..."`,
  `on` → `pl.before_*`;
- `on` — обработчики `game.before_*`;
- `game` — поля объекта `game` (например, `hint_verbs`);
- `init` — тело `init()` (логика или `|lua`);
- `start` — тело `start(load)`.

## impl

```
impl @compass:
  before Default(s, ev): |
    if mp.event ~= 'Drive' and mp.event ~= 'Walk':
      pass

impl box:
  before Take: |
    if s.score_value > 0:
      say [[уже брали]]
  on Take: |
    say [[берём]]
  after Drop: &on_drop

impl game:
  hint_verbs: { "#Exam", "#Walk" }
```

`impl имя:` назначает обработчики (`on X`, `life X`,
`before`/`after`/`post X`; `Any`/`Default` — как обычные события) и поля
(`hint_verbs`, `x`, …) уже существующему объекту (`_'объект'.before_Take
= ...`, `_'game'.hint_verbs = ...`) или классу (`impl Kitten:` пишет
`Kitten.method = ...`; экземпляры видят это через метатаблицу).
В обработчиках `s.field` типизируется по дополняемому объекту/классу
(owner-контекст), как внутри самого объекта; comma-ключ без фазы
(`a, b:`) — ошибка. `&fn` подставляет готовую функцию, а через
`include:` impl-блоки можно держать в отдельном файле. Поле
`dict: { ... }` даёт словарные формы: `_'game':dict { ... }`
(в т.ч. `impl game: dict: ...`). Поле `disabled: true`/`false`
отключает/включает объект (`_'объект':disable()` / `:enable()`).
Поле `var имя: значение` задаёт
переменную/поле как есть (`_'объект'.имя = значение`); в отличие от
обычных ключей имя не проверяется на события — так доопределяются
переменные, которых нет в декларации.

## verb

```
verb Tune:
  words: [на|под]строить,смен/ить
  patterns:
    - {noun}/вн : Tune
    - частоту|канал : Tune
  prio: 1

event Tune:
  on: |
    ...
```

- `tag` — тег (по умолчанию `#Имя`), `tag: false` — без тега;
- `words`, `patterns`, `prio`, `hint`;
- паттерны регистрируют событие: имя из правой части становится
  известным (`before Tune:`/`xaction(Tune)` без `event Tune:`), а слоты
  дают типы аргументов (см. «Сигнатуры обработчиков»); `Raw`-паттерны
  (бэктик) не разбираются;
- действия и обработчики события объявляются отдельно, в `event Имя:`
  (`on:` → `mp.Имя`, `before`/`after` → `mp.before_/after_Имя`);
  `on`/`before`/`after` внутри `verb` не поддерживаются;
- `remove #Tag:` снимает глагол: в том же месте файла генерируется
  `VerbRemove '#Tag'` (полей у `remove` нет; без голого `#Tag` — ошибка).
  Паттерны снятого глагола выпадают из сигнатур событий (сужение);
  событие, которое вводили только они, снова неизвестно — объявите его
  в `event Имя:` или `type event:`, если обработчики/`xaction` нужны.
  Неизвестный тег не диагностируется (в движке это молчаливый no-op,
  стандартные глаголы объявлены в Lua);
- имя события регистрируется паттерном, так что отдельное `event Имя:`
  нужно только для действий/обработчиков; без паттернов событие
  объявляется `event` или `extend type event:`.

## event (события и их действия)

```
event Reflect:
  on: |
    ...

event Say:
  before: Сообщить, что предмет пуст.

event Any:
  on: |
    when ev == Exam and w:has scenery:
      say осмотр декорации
    when ev == Wear:
      say надели
```

- `event Имя:` регистрирует событие; имя — как в движке (`Walk`, `Any`);
- `on:` — реализация действия (`mp.Имя = function(s, w, wh) ...`);
- `before`/`after` — `mp.before_Имя` / `mp.after_Имя`;
- `event Any:` / `event Default:` — глобальные правила (`mp.Any` /
  `mp.Default` и `mp.before_Any`/`mp.after_Any`): один блок на все
  события; параметры по умолчанию `s, ev, w, wh`, ветвление — через
  `when ev == …:` (ср. объектные `Any:`/`Default:`, которые
  срабатывают у конкретного объекта);
- пустое объявление просто регистрирует имя события (для `verb`,
  `before`/`after`-ключей и т.п.); объявляйте событие до/независимо
  от `verb` — `verb` теперь только слова и паттерны.

## extend (расширение существующих глаголов)

```
extend #Take:
  words: выкрасть

extend #Exam:
  patterns:
    - {noun}/вн {noun}/тв : Reflect
```

- со `words:` → `VerbExtendWord` (добавляет слова/шаблоны);
- только `patterns:` → `VerbExtend` (добавляет шаблоны-дескрипторы,
  слова остаются от исходного глагола);
- поддерживаются `prio`, `hint`.

## type (перечисления)

```
type attr: ~, alive, animate, broken, worn

extend type attr: coded, fed

# длинный список можно перенести `-`-строками
# (в элементе списка тоже можно через запятую)
type mood:
  - happy, sad
  - angry
```

(ведущий `~` — разрешить отрицания, см. ниже)

- значения — голые имена (через запятую или `-`-списком; в элементе
  списка тоже можно через запятую — так переносят длинные типы);
  кавычки запрещены; для `event` — только блок `имена: аргументы`
  (см. «Сигнатуры обработчиков»);
- `type` без значений и повторный `type` с тем же именем — ошибка;
- `extend type` неизвестного типа — ошибка (защита от опечатки в имени типа);
- проверяются литералы в слотах `fn` с этим типом, `attrs:`,
  `has`/`hasnt`/`attr`, а также в сравнениях `==`/`~=` (если одна
  сторона — выражение этого типа, литерал другой сверяется со списком);
- первый элемент `~` включает отрицание: `~X` разрешён, если `X` —
  допустимое значение (у `attr` включено); без `~` префикс отвергается —
  это позволяет типам вообще не иметь дела с отрицаниями (литеральное
  значение вида `~X` можно перечислить в списке как есть);
- базовые `attr` (атрибуты, с отрицанием; список метапарсера из
  `doc/metaparser/manual-ru.md` плюс `gameover`/`multi`), `direction`
  (`n_to`, `ne_to`, ..., `out_to`), `case` (падежи
  `им, рд, дт, вн, тв, пр, зв`), `gram`
  (граммемы `ед, мн, 2, од, но, мр, жр, ср, имя, фам, разг`) и `event`
  (все движковые события) объявлены в `stdlib.mise`; игры расширяют их
  через `extend type ...`, а события — ещё и объявлением `event Gaze:`.
  Без `include: stdlib` встроенные имена событий неизвестны.
- `ref` — «голое имя объявленного объекта»; специальный тип значений
  полей в `props:` (`ref`, `tbl[ref]`), в логике не встречается.

Тип — это обычная строка: проверка происходит только на сборке, в Lua
эмитится строковый литерал, но для компилятора это отдельный тип:
значения пишутся голыми (`s:noun(вн)` — по `case`, `s:has light` — по
`attr`), а строковый литерал в слоте перечисления — ошибка
(«enum values are bare, not quoted»). Составной хинт (`рд,2`) задаётся
таблицей: `s:noun({ рд, 2 })` — элементы по `tbl[case|gram]`, либо
голым значением/числом-алиасом (`s:noun(1)` — по `num`). В таблице
число, объявленное значением enum-альтернативы (`2` ∈ `gram`),
считается этим значением (`{ вн, 7 }` — ошибка). Значение перечисления
можно передать туда, где ожидается `str`, но не наоборот.

## Сигнатуры обработчиков (`type event:`)

```
type event:
  Answer, Ask, AskFor, AskTo, Consult, Tell: obj, str
  Burn, Cut, Dig, Tie: obj, obj?
  Give, Insert, Lock, PutOn, Remove, Show, ThrowAt, Transfer, Unlock: obj, obj
  life Ask, Tell, Answer: obj, str
  Inv, WaveHands, Look:
```

`type event:` можно объявить блоком: ключ — имена событий через запятую,
значение — типы аргументов `a1..an` так, как их передаёт движок (как в
`mp:Имя(a1, ...)`); пустое значение — аргументы неизвестны. Строка
`life Имя, ...: типы` задаёт аргументы `life_Имя` (первым идёт персонаж);
её имена должны быть объявлены выше в этом же блоке или в базовом типе.
`extend type event:` добавляет события и их сигнатуры тем же блоком;
список имён и inline-форма для `event` не поддерживаются (только блок).

Имена и аргументы событий берутся ещё и из паттернов `verb`/`extend`
(см. «verb»): имя — правая часть паттерна, аргументы — по слотам
(`{noun}` → `obj`, `*` → `str`; позиция без слота в части паттернов → `?`).
Источники объединяются: позиция необязательна, если её нет в одном из
них, а типы — union (`obj|str`). Поэтому `extend #Drop: patterns: {noun} :
PutOn` делает второй аргумент `PutOn` необязательным, хотя в таблице он
был обязательным. `remove #Tag:` убирает вклад паттернов снятого
глагола: объявленная таблица остаётся, выведенные из паттернов
аргументы — нет.

Типы подставляются в тела обработчиков по получателю:

| получатель | `s` | `w` | `wh` |
|---|---|---|---|
| `obj`/`door`/класс | a1 | a2 | a3 |
| `room`/`story`/`ending`, `game`, `event X:` | получатель | a1 | a2 |
| `life_Имя` | персонаж (a1) | a2 | a3 |

Имена параметров в генерируемом Lua не меняются (`s, w, wh`) — меняются
только типы. Типы **позиционные**: `s`, затем `ev` (у `Any`/`Default`),
затем аргументы события (`w`, `wh`, …); поэтому имена можно выбирать
свободно (`before AskFor(s, text):` — `text: str`, `before Cut(s, tool):` —
`tool: obj?`). Событие без записи — как раньше (`s`/`w`/`wh` — `obj`);
`Any`/`Default` — `s, ev, w, wh`.

Составной ключ (`before Ask, Cut:`) типизируется, только если у всех его
событий совпадают аргументы (с учётом фазы и получателя): `before Cut, Dig:`
даёт `w: obj?`, а `before Drop, Give, ThrowAt:` — нет (разные сигнатуры,
остаётся `obj`).

В теле обработчика типы хвоста сужаются по событию: `ev == X` (у
`Any`/`Default`) или `event() == X` (у любого) дают аргументы события `X`
до конца ветки и в `and`-цепочке; `~=` не сужает:

```mise
before Any: |
  when ev == Ask:
    say text_of(w)      # w: str
  when ev == Cut:
    if w:               # w: obj?
      w:has scenery
  default:
    pass
```

Стандартные сигнатуры — в `stdlib.mise`: события с текстом `*` — `obj, str`,
с необязательным вторым объектом — `obj, obj?`.

## talk (диалоги)

```
talk Разговор_с_Мариной:
  intro: [[-- вступление (необязательно)]]
  option:
    when: q1 == 1
    ask: Что тут случилось?
    reply: -- Какой-то взрыв...
    option:
      ask: Что с регенератором?
      reply: -- Работает...
    option:
      ask: Как с кислородом?
      reply: -- Запасов часов на пять...
      option:
        ask: Хватит, Марина!
        do: |
          say Я взял за плечо девушку...
          walkout()
          q1 = 2
  option:
    always: true
    ask: Я скоро вернусь.
    do: |
      say -- Хорошо, я поищу ещё баллоны...
      walkout()
  label дальше:
    say: -- продолжение...
    option:
      ask: ...
```

Поля фразы:

| Поле | Смысл |
|---|---|
| `intro:` | вступление (первая фраза; текст, логика, `\|lua` или `&имя`) |
| `ask:` / `say:` | текст варианта (`dsc`; текст, логика, `\|lua` или `&имя`) |
| `reply:` | ответ при выборе (`act`: текст, логика, `\|lua` или `&имя`) |
| `do:` | действие (`act`-функция; логика, `\|lua` или `&имя`) |
| `onempty:` | обработчик пустой фразы (`function(s)`; логика, `|lua` или `&имя`) |
| `when:` | условие доступности (`cond`): выражение, `true`/`false`, логика, `\|lua` или `&имя` (fn `-> bool`) |
| `always: true` | не закрывать фразу после выбора |
| `hidden: true`, `only: true` | как в phr |
| `next: имя` | переход `next = '#имя'` |
| `label имя:` | фраза-метка (вне дерева, крепится к dlg) |
| `option:` (вложенно) | дочерние варианты |

Вложенные `option:` — дерево; `reply:` + `do:` вместе дают функцию, которая
сначала печатает ответ, затем выполняет действие (если `reply` — функция,
она вызывается: `p(fn(s))`). Компилируется в обычный
`dlg { phr = {...}; obj = { <метки> }; }`, метки ищутся движком по `#имени`.
Поля фразы типизированы в stdlib скоупом `props option:` (`ask`/`say`/
`reply`/`intro` — `str | fn(s: obj) -> str`, `onempty` — `fn(s: obj)`,
`when` — `bool | fn(s: obj) -> bool`).

В `when:` доступен `s` — сама фраза (движковый `cond(s)`): и в выражении
(`when: not s:has(open)`), и в блоке (`when: |` + `return ...`).
Свободные поля фразы (не из таблицы выше) должны быть простыми именами —
иначе ошибка `bad talk field`, а не битый Lua.

## Генерация

- отступ — 2 пробела; между top-level блоками и вложенными декларациями —
  пустая строка;
- слова объектов генерируются как `-"..."`, поэтому словарь компилируется
  как обычно (`dict.mrd`);
- многострочные `[[...]]` не переотступаются (сохраняется текст);
- проверки на этапе компиляции: неизвестные события (регистр важен),
  дубли обычных имён (кроме `#тегов`), ссылки на необъявленные объекты
  (`with`/`found_in`/`take`), неизвестные имена/функции/методы внутри
  `|`, типы аргументов и `return` у `fn`, `words` обязателен для
  объекта.

## Ошибки времени компиляции

Всё проверяется до запуска; сообщение указывает место (`logic:N: ...`
для логики, `<объект>.<поле>: ...` для полей). `say`-фолбэк на сырой
текст срабатывает только на ошибках разбора — типовые ошибки
пробрасываются.

**Имена и ссылки**

- кавычки в именах деклараций, тегах, `attrs:`, событиях, значениях
  `type`/`extend type`, элементах списков — ошибка; имена — без
  пробелов и дефисов, `nam:` запрещён (имя = имя декларации);
- дубликаты обычных деклараций запрещены (совпадать могут только теги);
- `with`/`found_in` и поля-ссылки (`n_to`, `door_to`,
  `talk_to`, …) ссылаются на объявленные объекты; динамические цели
  задаются через `|lua`/бэктик;
- голые значения в полях объектов/классов, `impl`, `setup`/`hero`/
  `game`, `const`/`global` обязаны быть объектом, событием или значением
  перечисления (строки — в кавычках);
- объекты в логике — только голым именем: `_'...'` и строки в
  `obj`-слоте — ошибки;
- инстанс класса не может перекрыть унаследованный метод значением
  (`Door d: description: Текст`): STEAD3 падает на загрузке
  («Overwrited object method»), поэтому mise сообщает об этом сразу;
  метод перекрывается `|`, `|lua` или `&fn` (или полем в `impl:`);
- неизвестные имена/объекты/события/функции; неизвестная цель `impl`
  (не объект/класс/`game`/`@…`); неоднозначное голое значение
  («ambiguous value»); `&` класс-типизированной fn у неподходящего
  владельца; `&` неизвестной/inline-фн или `fn` в слоте не-`fn`;
  событие без фазы (`on`/`life`/`before`/`after`/`post`), comma-ключ
  в `impl` без фазы и блок `on:` в объекте; вызов метода, не
  объявленного как `fn`.

**Функции**

- сигнатура: неизвестный тип, `...` не последним, неверное имя
  параметра, дубликат `fn`, отсутствие `|`/`|lua`-тела;
- параметры ключа-обработчика — только имена: типы в скобках
  (`before Cut(s, w: obj?)`) — ошибка (типы берутся из `type event:`/
  `props:`);
- тело-выражение: `;`, `...`, `fn_` и повтор параметра запрещены;
- вызовы: арность (точная, у вариадических — минимум), типы
  аргументов, `fn` без `()` в позиции значения, отсутствие получателя
  у метода, `...` в логике, вызов поля/выражения.

**Типы**

- несовпадение типов в аргументах, `return`, присваиваниях;
- `any` не проходит в конкретный тип (аннотируйте источник:
  `fn ... -> T`, параметр, поле-литерал);
- `<`/`>`/`<=`/`>=` требуют `num` с обеих сторон (сравнение `obj`
  с числом в Lua падает);
- `T?` нельзя использовать там, где ждут `T` (методы, `obj`-параметры,
  поле/индекс) без сужения (`if o:`); `nil`-тип и смена типа локальной
  или поля — ошибка;
- перечисления: пустой `type`, дубликат, `extend type` неизвестного
  типа, кавычки/пробелы в значениях, неизвестное значение (с
  подсказкой `did you mean`), `~` без `negate`;
- `attrs:` и литералы `attr`/`has`/`hasnt` проверяются по типу `attr`.

**Синтаксис логики**

- табличные конструкторы `{}` и анонимные функции — только через
  `fn ... |lua`; `^` запрещён (объекты — `==`); `#` — только `#тег`
  (длина — `len()`);
- недопустимый lhs присваивания, неизвестное ключевое слово, неверный
  `for` (заголовок или границы не `num`), незавершённые строки/скобки,
  неожиданные отступы;
- смешение `when`/`default` с `elseif`/`else` в одной цепочке,
  `default:` без `when`;
- несовпадение подписи `&fn` (арность/параметры/возврат) и вызов
  fn-значения с неподходящими аргументами.

**Структура файла**

- неизвестные секции/декларации (`events:` больше нет);
- `extend` — только с голым `#Tag`; `impl` — с голой целью;
- `verb` не принимает `on`/`before`/`after` (действия — в `event`);
- `remove` — только с голым `#Tag` и без полей (`remove #Tag:`);
  `event` — только блок с полями `on`/`before`/`after`;
- `dict:` и `impl ... dict:` — только табличный литерал `{...}`;
- `setup` — известные ключи, `start` — `|`-блок; `type`/`extend type` —
  значения-имена без кавычек; `talk` требует имени; `include` должен
  существовать;
- `mixin`: дубликат/неизвестный/вложенный mixin, конфликт ключей
  двух mixins, привязанных к одному объекту.

Не проверяется (только рантайм): типы полей `setup`
(`s.field` там остаётся `any`); в обработчиках `impl` `s.field`
типизируется по дополняемому объекту. Голые значения полей везде
сверяются с именами на сборке. Цель `impl` должна быть объявленным
объектом/классом (или `game`/`@…`).

## Ограничения

- диалоги вне `talk:` пишутся «сырым» `phr`-литералом (в `|lua`/`lua:`);
- `|lua` / `lua:` остаются escape hatch для всего, что не покрыто DSL
  (внешние include, нестандартные функции);
- `remove #Tag:` сужает сигнатуры только по паттернам, которые видит
  транспилятор; повторная регистрация глагола в `|lua`/`lua:` не
  моделируется (сигнатура может стать уже реальной);
- **TODO:** не разрешить ли `extend type event:` перезапись сигнатуры
  (сужение) без снятия глагола — сейчас источники только объединяются;
- комментарии из `.mise` в сгенерированный Lua не переносятся.

Полные примеры:
- `tests/mise-cloak/game.mise` и `tests/mise-cloak-en/game.mise` —
  эталонные демо (`lang: ru`/`en`), ноль `lua`-блоков в логике;
- `tests/mise-heidi/game.mise` — минимальная игра с `ending`;
- `tests/mise-wtell/game.mise` — классы, события, `dict`, `setup.init`
  (один `lua:` — настройки движка);
- `tests/mise-alice/game.mise` — классы с демонами (`rnd`), поля-ссылки
  с `_(...)`, `extend #Exam`;
- `tests/mise-talk/game.mise` — `talk:` (intro/option/reply/do/when/
  next/always/hidden/only/label) с golden-транскриптом движка;
- `tests/mise-kinds/game.mise` — пресеты `door`/`story`/`ending`,
  фазы `on/life/before/after/post`, `type`/`extend type`/`extend refs`,
  `with`/`dict`/`disabled`, поля `setup` (hero/game/take/fmt), `verb`
  (tag/prio/hint);
- `tests/mise-events/game.mise` — типы обработчиков: `type event:`,
  `verb`-паттерны, сужение `ev == X`/`event() == X`, составные ключи,
  позиционные имена параметров;
- `tests/mise-remove/game.mise` — `remove #Tag:`: сужение сигнатур
  событий и `VerbRemove` в сгенерированном Lua;
- `tests/mise-stdlib/game.mise` — вызов каждой функции stdlib.

Все игры гоняются `tests/run-mise-tests.sh` (сверка Lua и, с
`--engine`, транскриптов оригинал/конверсия; игры без оригинала — с
`transcript.golden`).
