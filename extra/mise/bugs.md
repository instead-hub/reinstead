## Закрытое в 445f527 (перепроверено)

Ниже — что именно проверялось, чтобы при следующем аудите не переоткрывать.

### 1. Вызов `fn` ниже объявления и взаимная рекурсия

Эмиттер ставит forward-декларации: тела, на которые ссылаются *более ранние*
тела, выходят как `fn_x = function(…)`, остальные — `local function fn_x`.

```mise
fn even(n: num) -> bool
  if n == 0
    return true
  return odd (n - 1)
```
→ `local fn_odd` перед телами; в движке `even4=[true] f=[42]`.
Тест: `tests/mise-hof`. Заодно покрыты 3-звенные цепочки и `local function` для
саморекурсии (`i == j` в проверке исключён).

### 2. Отступ внутри многострочных литералов

`lua_lines()` (lexer) режет Lua-код на строки **вне** `[[…]]`, `--[[…]]`,
`'…'`, `"…"`, и `_ind()` больше не вставляет пробелы внутрь значения.

```mise
fn f() -> str
  return "a\nb"
```
→ `#s = 3` (было 5). Проверено на `"a\nb"`, `"""x\ny"""`, `[[q\nw]]` внутри
`lua`, `\`-переносе (`#s = 9`), и на блоке с `--[==[ ]] ]==]`, `"quote \"]"`,
`'single'`, `-- коммент с "кавычкой`. `lua_str()` добавляет `\n` после `[[`,
чтобы значение не начиналось с пробела при повторной эмиссии.
Тест: `tests/mise-say` (`ml={slen esc_ml},{slen tri_ml},{slen raw_ml}`).

### 3. `match` и `_`

`_` не может быть не последним армом и не может стоять с другими паттернами;
арм только из `_` даёт валидный Lua. Тест: `tests/mise-rules`,
`tests/mise-errors/match-wildcard-*.mise`.

### 4. Имя 0-арной `fn` в значении поля

`_prop_scalar()` учитывает `rk`: `dsc = f` → `dsc = fn_f()`. `dsc = wd` (у `wd`
есть параметр) — ошибка `wd: needs 1 argument(s)`. Шлюз не пропускает и
`fn f() = g` (тип `ANY`), поэтому «выпадающих» макросов в поле не попадает.

### 5. `const`

`K = 4` и `K += 1` — `K: a constant cannot be assigned`; чтение и `local K`
(shadow) проходят. Тесты: `tests/mise-errors/const-assign*.mise`.

### 6. `for … in`

Итератор обязателен: `for x in 5` → `for … in: expected an iterator, got num`.
`pairs`/`ipairs` в `core.mise` получили тип `fn() -> …`, поэтому
`for k, v in pairs box` типизируется. `of` не тронут.

### 7. `fn` с именем значения перечисления

Ошибка в обе стороны: `fn multi` при `attr multi` и `type X = … f …` при
существующем `fn f`. Тесты: `fn-named-as-enum`, `type-named-as-fn`.

### 8. Вариадик `...`

Работает: `fn va(...: num)`, `local a = ...`, упаковка `for v of [...]`,
`cannot use '...' outside a variadic function`, `cannot assign to '...'`.
Осталось: результат `select …` типизируется как `any`, а `#` на vararg нет
(`select "#" ...` → `return value 1 … expected num, got any`; обходится
`local v: any = select "#" ...`). Тест: `tests/mise-hof`.

### 9. Поля `T | fn(obj) -> T`

В позиции, где ждут `T`, поле читается как вызов: `str` → `std.call(o, 'f')`
(вызывает, если функция, иначе значение), остальное → `mp:runorval(o, 'f')`.
Проверено в движке (`room=текст от fn pri=6`), включая `==`, `in`, `match`,
интерполяцию, конкатенацию и `+=`; запись неверного типа по-прежнему ошибка
(`dsc: expected str|bool|fn(obj)->str, got num`).

Два ограничения, оставить как есть или доделать:

- нужна **позиция с ожидаемым типом**; `local t = box.dsc` даёт union, и `if t`
  сужает только `nil`, а не ветку-функцию. Так и задумано («сужение только по
  имени»), но в интерполяции это ловушка: `local t: str = box.dsc` — работает.
- форма `T | bool | fn` (`dsc`, `description`, `inside_dsc`): `bool` попадает в `vals`,
  а `_callable_field_ret()` возвращает только `union(*rets)` — то есть чекер
  объявляет `str`, хотя значением может быть `true`. Проверено:

  ```mise
  obj box "коробка" @ r
    dsc = true
  fn probe(s: obj) -> str
    local t: str = s.dsc
    return t .. "!"
  ```

  компилируется, в движке `attempt to concatenate local 't' (a boolean value)`.
  Фикс — вернуть `union(*rets, *(vals ∩ expected))`, т.е. «значение остаётся в
  типе, если оно само подходит»: ~3 строки в `_callable_field_ret` +
  `_eval_field_for`. Отдельно: если экземпляр объявляет конкретное значение
  (`dsc = true`), тип точен и eval не включается — ловушка только у
  класса/`obj`-приёмника.

### 10. `ref`-значение в `ref`-поле

Принимаются: объявленный объект, `none`, имя `ref`/`global`/`fn`/`lua`-функции,
лямбда (`&(s) cur`), блок (`n_to =` + `return cur`), `BinOp` с `and`/`or`.
Проверка стала типовой: `n_to = 5` → `expected ref|fn(obj)->ref, got num`,
`n_to = "q"` → `object reference must be a bare name`, `n_to = [q, q]` →
`expected ref|fn(obj)->ref, got tbl[room]`. Статическая ссылка проверена в
движке (`s_to = back` ведёт в комнату). Тест: `tests/mise-typed`.

Замечание: `n_to = cur` — это **копия значения на загрузке**; чтобы направление
менялось в игре, нужно поле-функция (`n_to = &(s) cur` или блок), иначе
переприсваивание `cur` в обработчике ничего не изменит. Стоит упомянуть в SPEC.

## 1. `extern global` — нужен ли он вообще?

**Закрыто: удалён.** Ниже — почему, что именно удалено и как мигрировать.

Короткий ответ: его можно было убрать целиком и заменить на `extern fn` +
`extern value`. Проверено, почему.

### 1.1. Что даёт `extern global`

`extern global` даёт `Sym(rk='lua_global')` с объявленным типом; дальше работают
только те операции, которые этот тип разрешает.

| Объявление | Что можно | Проверено |
|---|---|---|
| `extern global words: tbl = "words"` | `words[1]` → `words[1]`; `words[1] = 5` → `words[1] = 5`; `for w of words`; `pairs` | ✅ |
| `extern global extra: any = "extra"` | только само имя (`local x = extra`) | ✅ |
| `extern global extra: any = "extra"` | `extra.flag = true` → `unknown field 'flag'` | ✅ |
| `extern global extra: any = "extra"` | `extra = 5` → `unknown name 'extra'` | ✅ |
| `extern global math: any` | `math.floor` → `unknown field 'floor'`; вызвать нельзя (вызов только `имя args`) | ✅ |

То есть с `: any` объявление не даёт **ничего**, кроме права написать голое имя,
и при этом врёт: `core.mise:128` («Lua globals reachable from expressions
(`mp.event`, `math.floor`, …)») — неверно, а подсказка `use __floor` ведёт к
литеральному `.__floor` (`nil`), который нельзя и вызвать.

### 1.2. `extern value` — строгий надмножество

Тот же набор операций даёт уже существующий `extern value`, и даже больше
(та же таблица, но с `extern value words -> tbl = "words"`):

| Выражение | `extern global` | `extern value` |
|---|---|---|
| `words[1]` | `words[1]` ✅ | `words[1]` ✅ |
| `words[1] = 5` | ✅ | ✅ |
| `local x = words` | ✅ | ✅ |
| `for w of words` | ✅ | ✅ |
| `cfg.flag = true` (тип `any`) | `unknown field` | `unknown field` |
| присваивание имени целиком (`words = …`) | ошибка | ошибка |

Разницы в эмиссии и в диагностике нет: обе формы печатают шаблон как есть.
Единственное, что `extern global` «умеет» сверх, — ничего: чтение, индексация,
итерация и запись по индексу доступны и через `extern value`.

### 1.3. Сколько их реально используется

- в `core.mise` — 12 объявлений, **все `: any`** (`mp`, `std`, `game`, `pl`,
  `instead`, `snd`, `theme`, `io`, `os`, `math`, `table`, `string`), рядом 92
  `extern fn` и 8 `extern value`;
- в играх/тестах — **ноль**: все `mp.*`/`instead.*` (`mp.score`, `mp.undo`,
  `mp.detailed_inv`, `instead.notitle`) сидят в `lua`-блоках или в бэктиках
  (`fn cur_score() -> num = \`mp.score\``), т.е. мимо чекера;
- `impl mp` / `impl pl` (6 мест) — не связаны: цель `impl` сверяется по
  allowlist в чекере, а эмиттер пишет `_'mp'` по хардкоду `("mp", "pl")`.

Миграция: ни одна игра не пострадает, менять нечего.

### 1.4. Что удаляется и что добавляется

Удаляется 12 строк из `core.mise` + машинерия (~25 строк): ветка в
`_parse_extern`, `ast_nodes.GlobalDecl`, `Context.lua_globals`, ветка сбора в
`_collect_declarations`, ветка в `_infer_sym` (`rk = "lua_global"`), ветка в
`emitter._expr`, ключевое слово в SPEC §5. Плюс уходит класс путаных
диагностик вида `unknown field 'event' (use __event for dynamic values)`.

Добавляется вместо — типизированные обёртки, потому что «вызвать Lua-функцию»
через глобал невозможно в принципе (в языке вызов только `имя args`/`obj:meth`):

```mise
extern fn floor(v: num) -> num = "math.floor($1)"
extern fn upper(s: str) -> str = "string.upper($1)"
say "{floor 2.7} {upper box.nam}"     # rc=0
```

Минимальный набор, который стоит положить в `stdlib.mise`: `floor`, `ceil`,
`abs`, `min`, `max` (math); `upper`, `lower`, `sub`, `rep`, `fmt`
(string.format); `insert`, `remove`, `concat`, `sort` (table). Плюс `mp.args`
как `extern value args -> tbl = "mp.args"`, если понадобится итерация по
аргументам. Остальное автор объявляет сам — это 1 строка.

Для полноценных «объектов движка» есть отдельный механизм, `class list =
std.list` (типизированная таблица-класс) — `extern global` для этого не нужен.

### 1.5. Если жалко удалять

Можно оставить ключевое слово, но запретить `: any` в объявлении
(`extern global X: tbl = "…"`), тогда оно станет честным синонимом
`extern value` — но это третий способ сказать одно и то же. Удаление чище.

### 1.6. Сделано

Удалено:

- `core.mise` — 12 объявлений (`mp std game pl instead snd theme io os math table
  string`) и комментарий про «Lua globals reachable from expressions»; на их
  месте — подсказка про `extern value`;
- `parser._parse_fn` — ветка разбора; на `extern global` теперь ошибка:
  `` `extern global` is gone: a read-only alias of a Lua global is `extern value
  name -> type = "template"`, a Lua function is `extern fn name(...) = …` ``
  (закреплено `tests/mise-errors/extern-global.{mise,err}`);
- `ast_nodes.GlobalDecl` (и `lua_global` из комментария `rk`);
- `Context.lua_globals`, ветка сбора в `_collect_declarations`, ветка в
  `_infer_sym` (`rk = "lua_global"`);
- ветка `lua_global` в `Emitter._expr`;
- SPEC: грамматика `extern_decl`, §3.5 (теперь «глобал читается как

Миграция (проверено в движке):

`run-mise-error-tests.sh` 193/193 (192 + новый кейс).

Отложено по решению: обёртки `floor`/`upper`/`insert`… в `stdlib.mise` не
добавлялись — пока автор объявляет нужное сам одной строкой `extern fn`.
Если понадобятся, список в §1.4.

Сообщения тестов, которые пришлось обновить: `extern-bad-kind.err` (теперь

## 2. Нельзя ли `before Pull` на lua?

Можно — это **не ограничение языка, а недоработка чекера в одном месте**.
Эмиттер ветку `Lit(kind="lua")` для тела обработчика уже имеет
(`emitter.py:305`), а проверка подставляет `_HANDLER_VALUE = union(STR, BOOL, fn)`
(`checker.py:65`, `792`) и получает `got any`.

Проверил прототипом (3 строки в `checker.py:792`): `is_lua` → `want = None`.

```mise
impl game
  before Take =
    lua
      p("lua-handler: "..w.nam)
```
→ `_'game'.before_Take = function(s, w, wh) p("lua-handler: "..w.nam) end;`
в движке: `lua-handler: box`, `pulled` — работает, включая `w`/`wh`.

Смешанное тело (`say`, потом `lua`, потом `say` снова) — это ещё ~10 строк в
четырёх файлах: `LuaStmt` в `ast_nodes.py`, `if kw == "lua"` в `parse_stmt`,
ветка в `emitter._stmt`, `pass` в `checker._check_stmts`. Прототип проверен:

```mise
impl game
  before Pull =
    say "до"
    lua
      local n = w.nam
      p("lua: "..n)
    say "после"
```
→ `p "до"` / `local n = w.nam` / `p("lua: "..n)` / `p "после"`, транскрипт
`до lua: box после`.

Ограничение, которое останется в любом варианте: **локальные из `lua` не видны
чекеру** (`lua\n local n = 1` + `say "{n}"` → `unknown name 'n'`) — как и у
`lua`-блока целым телом. Это нормально (сырой Lua), но должно быть в SPEC.

Готов сделать обе части (3 + 10 строк, + 2 теста в `mise-*` и `.err` для
`before X =` + `str` + `lua` — по желанию).

## 3. Мелочи типизации — что нужно, чтобы исправить

Оценки по каждой, в порядке полезности.

### 3.1. `str?`/`num?` в интерполяции (~12 строк)

Сейчас `"{desc box}"` → `interpolation: expected str, got str?`
(`checker.py:1354`), потому что `_PRINTABLE` не содержит `nil`.

Нужно: (1) в `_infer` для `InterpStr` разрешить `T?`, если `without_nil(T)`
подтип `_PRINTABLE`, и пометить часть (`part.opt = True`); (2) в эмиттере
(`_p_call`/`_expr` для `InterpStr`) печатать `tostring(x or '')` для таких
частей. Вопрос семантики: `nil` → `""` (лучше для текста игры) или `"nil"`
(как сейчас ведёт себя `p(nil)`). Плюс 1–2 `.err`-кейса (например, `obj?` —
объект в интерполяции по-прежнему запрещён: нужен `noun`).

### 3.2. `len` для строки — **сделано**

`core.mise`: `extern value len(v: tbl) -> num` → `tbl|str`. `len "abc"` → 3
(байты: `#` в Lua считает байты, кириллица даст больше символов).
Тест: `tests/mise-stdlib` (`impl game / before Inv` печатает `len "abc"`,
транскрипт — `unpack 7 8 next 1 3`).

### 3.3. Параметры по умолчанию (~40 строк)

`fn f(a: num, b: num = 2)` сейчас не парсится (`expected ), got '='`).
Нужно: `_parse_param_list` принимает `= expr` и складывает в новый
`FnDecl.param_defaults: List[Optional[Expr]]` (не ломая кортежи `(имя, тип)`,
иначе правок становится вдвое больше); в чекере — только хвостовые параметры,
тип умолчания сверяется с объявленным типом, арность считается по числу
параметров без умолчаний (`required` уже считается через `is_optional`);
в эмиттере — пролог `if b == nil then b = <expr> end`. Плюс 3–4 `.err`-кейса
(умолчание не у последнего, неверный тип, умолчание на `obj`-параметре).

Дешёвая альтернатива на сейчас: `b: num?` + `if not b\n  b = 2` — уже работает.

### 3.4. Вызов произвольного выражения (~30–40 строк)

`box.on_tick 5` и `(math.floor) 2.7` невозможны: в `app_expr` вызывается только
`Sym` или `obj:meth`. Обход: `local f = box.on_tick` + `f 5` (работает, тип
`Fn`). Чтобы поддержать: `Call.callee: Optional[Expr]` в AST, ветка в
`parse_expr` после `primary` в скобках/поля, проверка типа `Fn` в `_check_call`,
эмиссия `(<expr>)(args)`. Полезно в основном для `mp.*`-хелперов (см. §1), т.е.
если выбран вариант «B» из §1, этот пункт не нужен.

### 3.5. Класс с одними объявлениями полей не попадает в `main3.lua` (баг)

Эмиттер пропускает класс, у которого нет слов, трейтов, обработчиков и полей
со значениями:

```mise
class crate_klass
  slots: num

crate_klass crate "ящик"
  slots = 2
```

→ `crate = Class {}` в `main3.lua` нет, глобал не создан, при загрузке
`Uninitialized global variable: crate_klass`. То же для класса только с
родителем (`class shelf_klass(obj)` + экземпляр). В тестах не покрыто:
`tests/mise-class` всегда даёт трейты (`class path(obj) : scenery`).

Причина пропуска двойная: (1) класс может быть объявлен кусками — `class path`
с полями и `class path(obj) : scenery` отдельно, и второй `Class { … }` затёр бы
первый; (2) часть классов вообще не должна эмиттиться — `class obj = obj`,
`class list = std.list` (конструктор движка), `choice` (только объявления
полей для чекера).

Пробовал чинить слиянием кусков в эмиттере (`_merge_classes` + `_class_usage`
+ `_class_has_body`, ~60 строк) — **откатил: слишком сложно и некрасиво**.
Более дешёвые варианты, если браться:

- держать в эмиттере `emitted: Set[str]` имён классов и пропускать кусок только
  если класс уже эмиттирован; «пустой» класс тогда эмиттится как `Class {}`
  (побочно в `main3.lua` появится `choice = Class {}` и подобные — безвредно);
- либо пропускать пустой кусок только когда имя класса ни разу не встречается
  как вид экземпляра или родитель (нужен проход по `prog.items`).

Пока — задокументировать в SPEC §3.6 как ограничение: «класс, объявленный только
полями, не создаёт глобал; чтобы иметь экземпляры, дайте ему трейт (например
`: static`) или значение поля».

## 4. Ведущие комментарии `lua`-блока теряются (найдено при проверке)

`_parse_lua()` (`parser.py:305`) режет `raw_lines` с строки токена `INDENT`, а
комментарии токенов не дают — первая строка блока теряется, если она
комментарий:

```mise
fn f1() -> num
  lua
    -- leading comment
    return 1
```
→ `local function fn_f1() return 1 end` (комментарий пропал). Комментарий в
середине блока сохраняется. Было и в `d719d59` (проверял на копии старой
версии), т.е. не регрессия. Фикс: брать начало блока не от `INDENT`, а от
строки после `lua` (`line + 1`), и отрезать по последней строке с отступом
`>= block_ind` — 3–4 строки в `_parse_lua`.
