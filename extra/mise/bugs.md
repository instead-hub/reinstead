## 1. `+=`/`-=` вычисляет индекс и получателя дважды

Касается и новых мест: `t[f()] += 1` (индекс считается дважды) и `extern
lvalue`-шаблона (`score += 1` печатает шаблон дважды).

```mise
t[idx] += 1        # → t[fn_idx()] = t[fn_idx()] + (1)   → idx вызван дважды
get.pri += 1       # → fn_get().pri = fn_get().pri + (1)
```
`_stmt` (`emitter.py:538-540`) форматирует левую часть один раз и подставляет
строку дважды. Проверено в движке: `calls=2`. Опасно, если индекс/получатель —
вызов с побочным эффектом (`have`, `pop`, выбор из списка): пишем в другой слот,
чем читали. Фикс: при нечистом индексе/получателе вынести их в `local` внутри
`do … end` (`_pure` уже есть) — ~10 строк.

## 2. Дыра в списке: `nil` посередине

```mise
local xs = [1, nil, 3]
say "{len xs}"     # `#xs` — не определено: 3 на LuaJIT, 1 на PUC
for i, x of xs     # `ipairs` останавливается на дыре — один элемент
  say x
```

`len` и `of` дают разное, оба молча: дыра в середине списка — это не «список из
`num?`», а неопределённый `#`. Стоит запрещать `nil` в литерале списка (кроме
конца) или хотя бы предупреждать.

## 3. `len` от таблицы-словаря

```mise
local t: tbl[any] = []
t["a"] = 1
say "{len t}"      # `#t` → 0: у словаря длины нет
```

`extern fn len(t: tbl) -> num = "(#$1)"` принимает любой `tbl`, а `#` осмыслен
только для последовательности. Различать `tbl[num]` (список) и `tbl[str]`
(словарь) в типе `len` — или не давать `len` для не-списков.

## 4. `==` для таблиц — это идентичность

```mise
say ([1, 2] == [1, 2])   # false — сравниваются ссылки, а не содержимое
```

Тихо неверный ответ для того, кто ждёт структурного сравнения. Либо запретить
`==` для `tbl` (кроме сравнения с `nil`), либо задокументировать.

## 5. Локальная переменная заслоняет имена, на которые опирается эмиттер

```mise
local p = 5
say "x"        # → local p = 5; p("x ") → попытка вызвать число
```

`say` печатается как `p(...)`, объекты — как `_'имя'`, функции — `fn.имя`,
`std.call` — `std`. Объявления `local p` / `local fn` / `local _` / `local std`
компилятор пропускает, и игра падает уже в движке. Стоит зарезервировать эти
имена (они и так не «пользовательские»).

## 6. Дубликат обработчика: побеждает последний, молча

`impl box` можно писать частями (патчи), но если один и тот же `before Take`
объявлен дважды, в файл попадают две функции подряд — работает вторая, первая
исчезает без диагностики. Для одного файла это почти всегда опечатка.

## 7. Лямбда в цикле видит последнее значение переменной цикла

```mise
for i, x of xs
  rawset fns, (len fns + 1), &(o) -> say "x={x}"
```

Эмитится `for i, x in ipairs(xs) do`, а замыкание захватывает ту же переменную
`x` — все лямбды увидят **последний** элемент (в Lua иначе и не бывает; так же
ведут себя `var` в JS и `lambda` в Python). Либо документировать, либо (если
лямбды в цикле — частый приём) эмитить `local x = x` в начале тела, когда в нём
есть лямбда.

## 8. Глубокая вложенность — traceback вместо диагностики

~250 вложенных скобок → `RecursionError` из Python. Фикс: `try/except
RecursionError` в `transpile()` → `Error("expression is too deeply nested")`,
5 строк.

## Что сознательно не делаем

- **Скобки вокруг шаблона** — не дело эмиттера. Шаблон — это одно Lua-значение
  (одно «место» для `lvalue`, один вызов для `fn`), автор библиотеки пишет его
  заранее и сам ставит скобки: вокруг всего шаблона (`"(($1) + 1)"`) и вокруг
  каждого слота в тесном контексте (`"($1):has($2)"`). Тогда вставка безопасна в
  любом выражении, и эмиттеру нечего угадывать.
  Позицию держит вид extern'а, но только в одну сторону: `extern value`
  инструкцией быть не может (это ошибка), а вот шаблон-значение, объявленный
  `extern fn`, проверкой не ловится — если его позвать инструкцией (`half 4` →
  `(($1) / 2)` → `((4) / 2)`), получится невалидный Lua при загрузке. Так же и
  обратное: макрос-инструкция в позиции значения (`say (bump)` →
  `p(mp.score = …)`). Это unsafe-уровень: по объявлению такое неотличимо от
  законного `time 5`, а шаблон мы не разбираем.
- Проверки **шаблонов `extern`** (слоты за пределами арности, запятая верхнего
  уровня, `--`) — шаблоны пишутся заранее в библиотеке, это unsafe-уровень:
  компилятор отвечает за типы аргументов, а не за буквы шаблона.

- `extern global` — удалён (был бесполезен, `extern value` покрывает).
  Lua-функции: `extern fn max(a: num, b: num) -> num = "math.max($1, $2)"`.
- Обёртки `floor`/`upper`/`insert`… в `stdlib.mise` — отложены, автор объявляет
  сам одной строкой.
- Порядок объявлений — **не важен**: эмиттер сам выстраивает файл (классы
  топосортом, `impl` последними, `verb` до `extend`/`remove`); цикл
  наследования — ошибка `inheritance cycle`. Тест `tests/mise-order`.
- Невидимые вызовы для полей `T | fn(obj) -> T` — **убраны**. Чтение поля
  отдаёт union как есть: `local d = s.dsc` — поле, `p s.dsc` — что там лежит
  (может быть функция), `local t: str = s.dsc` и `s.dsc .. "!"` — ошибка
  `expected str, got str|bool|fn(obj)->str`. Значение достаётся явно, обёрткой
  в игре (в `stdlib.mise` пока не кладём):

  ```mise
  fn expect_str(s: obj, f: str) -> str?
    lua
      local v = s[f]
      if type(v) == 'function' then v = v(s) end
      if type(v) == 'string' then return v end
      return nil

  fn expect_num(s: obj, f: str) -> num?
    lua
      local v = s[f]
      if type(v) == 'function' then v = v(s) end
      if type(v) == 'number' then return v end
      return nil
  ```

  `if d := expect_str s 'dsc'` → `d: str`. Имя поля здесь — строка, поэтому
  опечатку чекер не поймает; вариант без этого — отдельная обёртка на поле
  (`fn dsc_of(s: obj) -> str?` с `s.dsc` внутри). Работает и через `std.call`
  (короче, но падает на числах). Обёртка вида `expect_val(w: any)` **не**
  вызовет функцию: в неё приходит само значение, без объекта.
